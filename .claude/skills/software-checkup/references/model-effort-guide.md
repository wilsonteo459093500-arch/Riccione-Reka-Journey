# 用什么 model、什么 effort、几时开新对话

> 核对日期：2026-11-19（型号和指令查自 Claude Code 官方文档和 `claude-api` skill）。
> 型号和价钱会变。超过两三个月没更新，先用 `claude-api` skill 和 `claude-code-guide` 帮手核对，再照这份给建议，并把这份改掉。

## 现在有的 model（由强到省）

| Model | 特点 | API 标价（每百万字输入 / 输出） | 相对花费 |
|---|---|---|---|
| Fable 5.2 | 最强，适合最难、最不能错的事 | US$8 / US$40 | 约 Opus 的 2 倍 |
| Opus 5.5 | 日常主力，照计划做功能很稳 | US$4 / US$20 | 基准 |
| Sonnet 5.5 | 快、省，小改和日常问答 | US$2 / US$10 | 约 Opus 的一半 |
| Haiku 5.5 | 最便宜，简单重复的事 | US$0.10 / US$0.50 | 很少 |

订阅方案不是按这个价钱算，但用得越强、想得越深，5 小时额度掉得越快，比例大致相同。官方没有公布各 model 扣额度的准确比例。

## Effort（想多深）

`low` → `medium` → `high` → `xhigh` → `max`。现在这四个 model 的默认都是 `medium`。
越高想得越久、用量越多；只有难题才值得往上调。

## 怎么选（照这张表给建议）

| 要做的事 | Model | Effort | 说明 |
|---|---|---|---|
| 软件体检、定方向、排计划 | Fable 5.2 | high | 一年几次，值得用最好的 |
| 跟钱有关的规则（价格、折扣、报价算法）、资料同步、资料安全 | Fable 5.2 | high | 错了代价大。先 high，查不出来才 xhigh |
| 很难的 bug（修了两次还不对） | Fable 5.2 | xhigh | 开新对话，把现象讲清楚 |
| 照写好的计划做一个阶段（一般功能、画面） | Opus 5.5 | high | 大部分开发工作在这里 |
| 小改：改字、换图、调版面、改一个数字 | Sonnet 5.5 | medium | 同一个对话可以连续做几个 |
| 问问题、查资料、整理文字、写文案 | Sonnet 5.5 | low–medium | |
| `max` | — | — | 几乎不用；只有时间和用量都无所谓时 |

三条经验：

1. **先选对 model，再调 effort。** 新一代 model 用低一点的 effort，常常比旧 model 用高 effort 还好。
2. **从 `high` 开始。** 结果不够好才往上调；不要一上来就 `xhigh` / `max`。
3. **看「做完一件事」总共花多少，不是看单次。** 便宜的 model 来回改三次，比贵的一次做对更花。

## 怎么切换（云端对话 / 手机 app）

- 换 model：输入框旁边的 model 菜单，或打 `/model sonnet`、`/model opus`（对话中途可以换）。
- 换 effort：打 `/effort high`（`/effort auto` 恢复默认）。
- **ultracode（多检查员模式）**：`/effort ultracode` 开，`/effort ultracode off` 关；或者只在某一句话里打「ultracode」，就只有那一件事用。官方写明它用量大、会更快碰到额度。
  - 平常**关着**。只在「全面体检」和「上线前总复查」时开，而且要在刚开一个新的 5 小时窗口、这段时间不做别的事的时候。
  - 2026-11-19 的教训：开着 ultracode 做体检，14 个检查员两次都在几分钟内把 5 小时额度用完，一个都没跑完。
  - `/config` 里的「Dynamic workflow size」是一次最多派几个帮手的建议值：small（少于 5 个）、medium（少于 10 个）、large（少于 50 个）。额度紧就用 small。
- `/fast` 快速模式：同一个 model 出字快很多，但另外从 usage credits 扣钱，不算在方案额度里。一般不用开。

## 几时开新对话

**开新对话：**

1. 一个阶段做完、你说了「合并」→ 下一阶段开新的。（一个阶段 = 一个 PR = 一个对话）
2. 换软件、换主题。
3. 规划和动手分开：体检 / 排计划一个对话，动手做另一个。
4. 对话很长了：出现「前面的内容已摘要」、开始忘记前面定过的事、越回越慢。先说「把进度和决定写进 CLAUDE.md」，再开新的。
5. 同一个问题修了两三次还不对 → 开新对话、换强一级的 model，把现象重新讲清楚。旧对话里错的思路会一直带着走。

**不用开新对话：**

- 同一阶段里看了预览之后的小调整。
- 接着问刚才那件事的问题。

**新对话开场白**（`CLAUDE.md` 每次都会自动读，所以不用重讲背景）：

```
继续做 <软件>（<文件夹>，分支 <分支名>）。
照 docs/checkups/<软件>-<日期>.md 的第 <N> 阶段做。
先出预览给我看，我说「合并」才合并。
```

想省额度时在开场白后面加一句：「不要用 workflow，一步一步做。」
