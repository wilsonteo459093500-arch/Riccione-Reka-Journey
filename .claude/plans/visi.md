# VISI（invite/）体检与计划

> 这份放在 `.claude/plans/`，不放 `invite/PLAN.md`：`invite/` 整个资料夹直接上线，放进去会变成公开网页，合并时还会触发正式版部署。
> 开场白：「读 `.claude/plans/visi.md`，做体检计划第 N 阶段」

## 体检 2026-11-19（照 `app-checkup` 的格式整理；这次是它建好之前跑的）

### 怎么查的、查到哪（照实写）

- 线上状态我自己查（Vercel 只读）：
  - 正式版 `visi-riccione-reka.vercel.app` 停在 **#57（11 月 5 日）**。#74（11 月 18 日合并，动了 `invite/`）在这个项目里**没有任何部署记录**
  - 原因很可能是 **Vercel 免费版一天 100 次部署的上限**：11 月 19 日这个帐号确实撞到了（三个项目都回 `Deployment rate limited`，错误码 `api-deployments-free-per-day`）。#74 那一次本身没有留下记录，所以是推断
  - 环境变数有 `SESSION_SECRET`、`CATALOG_KEY`、`VISI_TEAM_PASSWORD`、`BLOB_STORE_ID`；**没有 `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`**，`BLOB_STORE_ID` 指的那个 Blob store 查不到 → 线上的「公司案例库（云端）」很可能用不了，只有本机模式能用
  - 过去 7 天没有任何运行报错（符合「还没人用」）
- 原本派 7 路 + 3 位复核。帐号的 5 小时用量上限撞了，结果是：
  - **完整查完 2 路**：电脑上实际走一遍（11 条）、手机 / iPad 上实际走一遍（12 条）。都用 Playwright 真的点、截图
  - **没跑的 5 路**：核心规则与资料安全、导出压测、给客户看的内容准不准、安全与隐私、工程健康
  - **复核一个都没跑成**。代替做法：最重的 6 条我自己对过代码，全部成立（标 ✔）；手机顶栏那条我看过截图（标 ✔）
- **没查到的**（第 1 阶段要补）：
  - 保存失败 / 空间满 / 两个分页同时改会不会丢资料；方案 `.json` 旧版和坏档
  - 导入的 `.json` 会不会带恶意内容（同事互传是日常）、登入和权限、客户名字会不会漏出去。repo 是公开的
  - 系列的设计理念、卖点、需求做法有没有逐字照公司手册；中英文是否讲同一件事（我只快速对过：五个系列的中英文名字跟 `riccione-company-profile` 一致）
  - 长名字、很多空间时 PDF / PPTX 的版面；PPTX 在 WPS / Keynote
  - 真 iPhone / Android：点输入框会不会自动放大、导出 PDF 是不是 16:9、Safari 一段时间没开会不会清资料

### 面试结论

| 问 | 答 |
|---|---|
| 「streaming responses + remaining time」 | 指对话时边做边报进度和剩余时间，不是要改 VISI |
| 现在用到什么程度 | **还没正式给销售用** |
| 销售用什么设备 | 电脑 / 笔电 + 手机 |
| 最想提升什么 | 四样都要：更快少手动、更好看更有说服力、稳定不丢资料、团队一起用 |
| 为什么还没用起来（第二轮） | 四个原因都有：还没培训、图库照片不够、销售习惯原来的做法、方案还没到他要的样子 |
| 剩下的体检怎么办（第二轮） | **先补完再动手**（用量恢复后开新对话，省量版） |
| 手机要做到哪一步（第二轮） | **做轻的**：贴需求卡、看清楚预览、复制文案发 WhatsApp；导出留给电脑 |
| 方案要不要存公司云端（第二轮） | **要，排进计划** |

**还没答的（新对话先问）**：方案哪里还没到他要的样子（图片 / 文案 / 版面 / 内容结构）；线上几时更新到最新版；新方案的语言预设；下面的阶段顺序可不可以。

### 做得好的（改的时候别弄坏）

- 快而且稳：两轮实测全程 0 个程序错误；贴需求卡 0.1 秒出 18 页，PDF 2.4 秒，PPTX 1 秒
- 导出忠实：PDF 正好 16:9、一页一张；PPTX 逐页对得上 PDF、每页有讲稿，没装品牌字体版面也没乱
- 体检清单具体、能照着做（每条有「去改」、有红项时导出前会先问）
- 诚实的保护有效：示范方案不会被盖掉；时段没确认前写「建议的时段」
- 手机上功能都跑得通（贴卡、平面图点编号、上传、复制文案、导出 PPTX），没有横向滚动；「加入主画面」条件齐全

### 发现

**一、会出事，先修**（会让客户看到错的东西）

1. ✔ **上传的照片会跑到别的客户的封面**：销售替 A 客户上传的空间照片，会自动变成 B 客户方案的封面和邀约页，连做好的旧方案也被换图，体检不提醒（`model.js` 的 `score()`：`if (c.own) return 100 + g`，`ROOM_SLOTS = { cover, invite }`；`app.js:736` 上传进共用图库）
2. ✔ **两位客户会混成一份**：在已有客户的方案里贴另一位的需求卡，确认框按「确定」就并进去，原稿不能复原（`app.js:432-446`）
3. ✔ **开场短话的页码会指错**：改过之后「第 N 页」定死，之后加平面图、开关页面也不变，体检还打勾（`app.js:349-353`，`check.js` 的 `typed()` 只量长度）
4. ✔ **客户自己打的字被悄悄丢掉**：「其他：神台」不会加空间；「最想解决」第 4 句以后不要，都没有提示（`data.js` 的 `MB.SCOPE_ROOMS` 只认 8 种，`brief-parse.js:141-142` 的 `.slice(0, 3)`）
5. ✔ **贴华文需求卡出英文方案**：新方案一律预设英文（`model.js:53`）
6. **英文客户写一大段，整段被当成一句原话**：方案页印 7 行，WhatsApp 讯息和讲解稿整段照抄（✔ `brief-parse.js:141` 英文句号不分句；`copy.js:402`、`:545`）
7. **线上是两周前的旧版**，而且云端案例库没接上（见上面「线上状态」）
8. **方案只存在浏览器里**：VISI 没有请浏览器「别自动清掉」，也没有像案例库那样提醒 Safari 用户（`store.js` 没有 `storage.persist`；对照 `caselib/local-sw.js`）。Safari 的行为待真机确认

**二、让它真的用起来**（用户说的四个卡点 + 手机）

1. ✔ **手机 / iPad 竖屏一打开看不到步骤**：顶部品牌栏盖住「①–⑤ / 图库」和「体检 / 导出」（`visi.css:35-51`、`:272-275`，`form.css:11-12`）
2. **手机上贴完需求卡看不到结果**：预览在编辑区下面约 4 屏，没有「看预览 / 回编辑」（`visi.css:35-41`，`app.js:260`）
3. **手机上看不清、按不准**：方案页缩到 0.28 倍，正文约 4px，点页面是跳去编辑不是放大（`app.js:2162-2166`、`:2222-2225`）；主要按钮 31px 高，缩图上「删除 / 左移 / 设主图」22×22 挨在一起，误删不能撤销（`visi.css:16-19`、`:110-123`）
4. **手机顶栏的「复制」「删除」和「图库」被挤到屏幕外**；HEIC 读不出来只说「0 张」（`visi.css:42-54`，`app.js:1479-1499`）
5. **图库照片不够**（用户说的）：内置图库没有浴室 / 梳妆台 / 神台；选图时厨房写 15 张，其中 9 张是选不了的「系列页专用」；公司案例库云端没接上
6. **没有上手引导**（用户说还没培训）：第一次打开只有一句「按＋新方案」。照 ①→⑤ 做到体检没有红橙项，实测要 8–12 分钟
7. **方案还没到用户要的样子**：哪里不够还没问到（见「还没答的」）
8. ✔ **⑤ 文案改过的字，刷新就没了**（`app.js:32` 的 `copyEdits` 只在记忆体）
9. **同事之间只能靠导出 `.json` 互传**，换电脑方案就没了，老板看不到大家做了什么 → 用户决定要做云端共用

**三、用起来更顺**

- 改左边时右边预览不会跳到正在改的那一页；体检「去改」只带到分页最上面（`app.js:2188-2225`）
- 选图弹窗写「最多 4 张」，页面只印 3 张，选满马上被体检提醒（`app.js:1892`、`:2021`）
- ④ 页面开关勾了之后缩图不更新；开关一页会让别的页自动图换掉（`app.js:1188-1194`，`MB.deckImages`）
- 方案清单分不清：导入的同名、没有日期；「＋新方案」每按一次多一份「未命名客户」；坏档出英文技术讯息（`app.js:144-151`、`:1844-1861`、`:2289-2296`）

**四、可以晚点**

- 首次打开约 4–5 MB、77 个请求；Google Fonts 的样式表会挡住第一次显示（本机量的，线上数字没量到）（`visi.html:17-26`、`:379-400`）
- script / css 没有版本号；开着的旧页面不知道有新版
- 断网时重新整理只得到断线页，本机存着的方案也看不到（没有缓存外壳的 service worker）
- 手机「导出 PDF」只是叫出系统打印，提示是电脑版说法（用户已决定导出留给电脑 → 手机上改成引导去电脑或用 PPTX）
- VISI 的核心规则（需求卡解析、文案拼句、体检、版面）几乎没有自动测试，只有公司案例库那一段有浏览器测试 → 第 2 阶段修的每一条都顺手补测试

### 分阶段计划（草稿：顺序还没最后确认；每个阶段开一个新对话，最好在用量刚重置后开始）

开场白：「读 `.claude/plans/visi.md`，做体检计划第 N 阶段」

| 阶段 | 目标（做完你会看到什么） | 做什么 | model · effort |
|---|---|---|---|
| 0 你自己能做的 | 线上的 VISI 是最新版；云端案例库接上 | ① Vercel 部署额度恢复后，把正式版更新到最新（可以请 Claude 触发，做完要确认真的更新了）② 照 `invite/README.md`「一次性设定（老板）」在 Supabase 跑 SQL、在 Vercel 加两个环境变数 | 不用写代码 |
| 1 补完体检 | 这份计划变完整：安全、丢不丢资料、内容准不准都看过 | `app-checkup` 省量版，派 4 路：`security` `dataops` `logic` `product`（`product` 的提示里加「系列和卖点逐字对公司手册」）。`uxapp` 已做完，把上面的发现写进 `facts`。先问完「还没答的」 | Opus 5.5 · high |
| 2 不会发错东西 | 发给客户的方案不会串图、混名字、指错页、漏掉他写的字 | 「一」的 1–6，每条配自动测试（VISI 核心规则的第一批测试）。开工前定：封面自动图的规则、语言预设 | Opus 5.5 · high |
| 3 手机轻量可用 | 手机上能贴需求卡、看清楚方案、发文案 | 「二」的 1–4；先给 2–3 种手机版面选；导出在手机上改成引导去电脑 / PPTX；用户真机试 | Opus 5.5 · medium |
| 4 图库够用 | 每个常见空间都配得到像样的图 | 补内置缺的空间（要用户提供照片）；选图数字不算选不了的；确认云端案例库能登入、能挑图 | Sonnet 5.5 · medium |
| 5 方案到位 | 做出来的方案是老板愿意发给客户的 | 先 brainstorm：用户指出不满意的页、给参考；再改 | Opus 5.5 · high |
| 6 更顺手 | 做一份方案少卷动、少困惑 | 「三」全部 + 文案改过会保存 | Sonnet 5.5 · medium |
| 7 让销售用起来 | 新同事第一次打开就知道怎么做 | 第一次打开的引导 + 一页教程 + 找 1–2 位销售试用、收意见 | Sonnet 5.5 · medium |
| 8 团队共用 | 方案存在公司云端：换电脑也在、同事能接手、老板看得到 | 先 brainstorm（登入、同步、两个人同时改、费用）；再分两三个对话做。先做小的：请浏览器别清资料 + 提醒备份 | Opus 5.5 · high（档案多或试过没做好才 Fable 5.2 · high） |
| 9 更快、能离线（可选） | 打开更快、没网也开得了 | 「四」的前三条 | Opus 5.5 · medium |

**推给销售的最低门槛**：阶段 0、1、2，加上阶段 3 的第 1 条（步骤栏不被盖）。
