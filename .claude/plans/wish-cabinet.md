## 用户的决定（2026-11-21 面试）

- **在哪里看**：两个都要。先在客人家的 3D 里看整体，点一个柜子拉近到单独的特写台。
- **重点细节**（用户点选的先后）：门板款式和拉手 → 颜色分组 → 工艺特写 → 打开看里面。四类都要。

- **怎么对比**：同一个画面一键切换 A / B。

- **手册**：用户在新对话里上传整本《SAIL 产品标准设计手册》PDF（216 页）。
- **参考**：CabinetFlow AI（cabinetflowai.com）、prompt2cad.com 这个环境打不开（网络规则挡住）。用户发截图 / 录屏，只参考做法，不抄素材。用户还提过「cabinet maker」一类的链接，仓库里没有记录，等用户一起发。

## 每个阶段都守住的

- 旧方案、案例、分享链接的画面一个像素都不变，用测试锁住（鸟瞰像素检查 `scripts/walk-pixels.mjs`）。
- 客人只看到名字（如「7号 · 黑胡桃乱纹」），不看工厂代号和价钱；设计师看代号，导出带代号。
- 款式、拉手、尺寸只照手册；手册没有的不编，标「示意」或不做。
- 工艺文案只用老板审过的：`.claude/skills/interior-design-expert/references/cabinet-craft.md` 第四节。
- 全程不用 AI 看图，AI 费用为 0。测试里不叫真的 Gemini。
- 新功能按需才载入：3D 工作室入口现在 397.14 kB，上限 397.5，只剩约 0.4 kB。
- 「我们做」只标定制柜、墙板、门、台面；活动家具是「示意」。
- 每阶段：开新对话 → 做完开 draft PR，附预览链接和截图 / 录屏 → 用户说「合并」才合。推送攒着推。

## 阶段

时间是对话里的工作时间，粗估；每阶段开头重估。

| 阶段 | 做完用户能看到什么 | Model · effort | 大约多久 |
|---|---|---|---|
| 0 用户准备 | 看完 PR #65 说行不行；整本手册 PDF；参考截图 / 录屏 | — | 用户的时间 |
| 1 设计稿 | 样图：点柜子后的面板、特写台、A / B 切换长什么样；能选哪些东西的清单。用户选了才动手 | Fable 5.2 · high（用量紧就 Opus 5.5 · high） | 1.5–2 小时 |
| 2 拉手 + 颜色分组 | 地柜、吊柜、高柜、中岛、电视墙、衣柜、鞋柜、书柜、浴室柜、墙板各一个色；柜体、柜门、抽屉面、侧板、踢脚、开放格分开；手册 §5 的拉手和颜色；4 个一键搭配（上浅下深、双色厨房、原木侘寂、全屋统一） | Opus 5.5 · high | 4–5 小时，多半拆成 2a 颜色、2b 拉手两个对话 |
| 3 单个柜子 + 特写台 + A / B | 点任何一个柜子：拉近到特写台转着看、单独改；方案 A / B 一键切换；「走进去」里也能用 | Opus 5.5 · high | 4 小时 |
| 4 门板款式 | 平板、线槽、框门、格栅、玻璃、藤编 / 编织、骨骼线，照手册（要先有手册） | Opus 5.5 · high | 4–5 小时，可能拆两次 |
| 5 工艺特写 | 特写台上近看门边、收口、踢脚、脱缝等做工；配老板审过的说明 | Opus 5.5 · high | 3–4 小时 |
| 6 打开看里面 | 打开柜门和抽屉；衣柜挂杆、抽屉组、层板、灯带 | Opus 5.5 · high | 3–4 小时 |
| 7 交接 + 上线检查 | 设计师导出带门板、板材、拉手代号；尺寸对齐手册标准，不标准的标「柔性定制」；中英文；全套上线检查 + 独立审查 | Opus 5.5 · medium | 3 小时 |

合计约 23–27 小时，7–9 个对话。

- 做到第 3 阶段（约 10–11 小时）设计师就能当场展示。那时先上展厅 iPad 试，再定 4–6 的先后。
- 每个对话只做一个阶段，别撞 5 小时上限。派出去的人用 Opus 5.5 · high，不派「怀疑者」。
- 第 4 阶段开工前手册没到：门板只做最基本的几款并标「示意」，手册到了再换。
