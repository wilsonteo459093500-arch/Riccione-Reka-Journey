### 地基（试做验证过的做法）

1. **数据全部是「没填就照旧」**。方案上加一块柜子设定（每组各部分的板材、拉手、门板款式）+ 单个柜子的例外 + 方案 B。取色顺序：单个柜子 → 这一组 → 上表「没设时跟谁」。没有这块数据的方案一个新材质都不建。
2. **每组一个自己的材质**，只在这组设了不一样的板材时才建：
   - 贴图按板材共用（`matlib.js` 的 `textureFor` 按 `matId|variant|res` 存），不会多占显存
   - 新材质的 `userData.slot` 要写 `'cabinetry'`：`compact()` 靠它给板材错开纹理，`Engine.slotAt` 和走进去的 `walk/paint.js` 靠它认表面。另外记一个「哪一组」，发金光和客人刷色用
3. **`furniture.js` 现在把 `'cabinetry'` 写死在每个柜子里**。试做用「这件家具是哪一组」的全局标记 + `mat()` 里换 key，吊柜那一段单独换；柜体色只在侧面看得出（衣柜试过）。正式做时让 `buildItem` 传一个「问哪个部分用什么」的小函数。
4. **特写台用同一个引擎、同一块画布**（iPad 开不起第二个 WebGL）。试做约 40 行：藏起 `stack.group` → 加一个圆台和背板 → `buildItem` 建一件放上去 → 转到正面朝太阳 → 把 `shadowPts` / `shadowRecv` 收紧到台子 → 换 `scene.background`。正式做还要：进出的动画、退出时把背景 / 影子 / 镜头原样放回、台上固定用白天的光。
5. **入口那一包会超**：现在 397.14 kB，上限 397.5。试做只加颜色位就到 397.62，再加特写台和 3 款拉手到 398.33。所以面板、特写台、拉手的形状、搭配全部放进「点到才下载」的一包（像 `walk/`）；有柜子设定的方案，在建 3D 之前先等这一包。`furniture.js` 里只留一个很小的口子。口子自己可能就要 0.3–0.6 kB：第 2a 阶段开头先量，不够就问用户能不能把上限放宽一点。
6. **分享链接 `#s=` 带整个方案**，柜子设定会跟着走；第 2a 阶段查一下链接长度够不够。
7. **每阶段合并前**：`npm test`、`npx vite build`、`node scripts/chunk-size.mjs`、`node scripts/walk-pixels.mjs --check`（20 个画面逐像素）。新加一条测试：没有柜子设定的方案，每个柜子问到的都是原来的颜色位。

### 做了什么

- 设计师：工具条「⋯」→「柜子：每组一个色」→ 左边面板。4 个一键搭配；这个家有的每一组一行，点开是各部分（柜门、抽屉面、柜体、侧板、开放格、踢脚）。选一行，再点下面的板材；或直接把板材拖到柜子上（换的是那一组）。点一行那组发金光。能撤销、自动保存、分享链接带着走（链接多约 140 个字）。
- 客人（许愿模式）：没有入口、看不到面板；方案分过组的话，3D 照分组上色，刷柜子只换刷到的那一组。
- 两种情况不走分组、照原来的路（全屋柜体一起换）：柜子是客人家里留下来的（锁住：原来的路会先问一句）；把板材拖到标签 / 材质板的「柜体」上。
- 10 组：地柜、吊柜、高柜、中岛、电视柜、衣柜、鞋柜、书柜、浴室柜、其他柜（餐边柜、展示柜、神台、玩具柜）。梳妆台是活动家具（`offer.js`），不分组。
- 柜体和侧板不是同一块板时，柜体两头贴一片 2mm 的侧板（原木侘寂：深色柜体、木纹侧板）。

  - `model.js` 规则（纯 JS）：`cab = { v: 1, g: { 组: { door, drawer, body, side, open, plinth } } }`，`decide()` 给材质钥匙，`applyPreset()`
  - `seed.js` 一键搭配的 6 块板（手册资料）；`runtime.js` 引擎那一半（`CabRuntime`）；`Cab.jsx` + `cabinet.css` 面板；英文在 `src/shared/i18n/en-cabinet.js`
- 入口里的口子（一共这几处，别的都没动）：
  - `furniture.js`：`CAB`、`K(部分, 组, 原来的颜色位)`；每件定制柜的每个部分都经过 `K()`；`buildItem` 里 `IT = item`、合并前 `CAB.h(item, raw)`
  - `StudioApp.jsx`：`Cab`（lazy）、`cabOn`、`snap` 里的 `cab`、`dropMaterial` 第一行问 `CAB.drop`；`Toolbar.jsx` 菜单一项；`store.js` 的 `packProject` 带 `cab`
- 做法和「地基」写的有两处不一样：
  - 材质直接放进 `MatLib.slots`（钥匙 `cab:<组>:<部分>`），贴图、画质、显存淘汰全走 MatLib 原来的路；没设的组用「跟着原来颜色位」的材质（`cab:<组>:~cabinetry`），`runtime.js` 包了一层 `lib.apply` 让它们一起换
  - 没有「建 3D 之前先等这一包」：方案有 `cab` 时先按旧样子建，这一包到了（几十毫秒）再把柜子重建一次。第一次打开会闪一下一个色
- 手册颜色的 6 块板（id `sail-m-…`）只放进 `MAT_BY_ID`，不进板材库、不进板材栏；方案里存的是这个 id，画的时候 `realOf()` 换成这台设备上同编号的真板材

### 坑

- **入口打包的目标不认 `?.`**：`CAB.h?.()` 会被展开成更长的代码，入口反而变大。写 `CAB.h && CAB.h()`。
- 这一包多 import 入口里的一个东西，入口就多几个字节（要多导出一个名字）；带 CSS 也算（预载清单里多一个档名）。
- `scripts/walk-pixels.mjs` 的 `openCase` 每次载入页面都会把 localStorage 写回样本：不能用「重新载入」验存档，要把 `cab` 直接放进开机的样本（scratchpad 里的做法：自己调 `initScript`）。
- 这台机器 `--check` 一轮 14 个画面要 25–30 分钟（高清档一张 3–4 分钟），基准要从没改过的那一版另外打包、另外拍一次。
