# RICCIONE REKA JOURNEY

溪岸 · 邀约体验网站

给「WhatsApp 聊上 → 填需求卡 → 做初步方案 → 发邀请函 → 客人到馆」这条动线做的一套静态网页。
纯 HTML / CSS / JS，没有构建步骤、没有后端 —— 丢到任何静态托管上就能用。

```
客户在 WhatsApp 聊上
      ↓
① brief.html    客户需求卡（客户填，3 分钟）
      ↓          填完 → 内容自动回到销售的 WhatsApp
销售读需求卡 → visi.html（VISI）做一版初步方案（导出 PDF）
      ↓
② index.html    邀请函（带客人姓名 · 日期 · 邀请人）
      ↓
客人到馆
```

`create.html` 是销售端的内部工具，一次填资料，同时生成上面两条链接和对应的 WhatsApp 文案。
`visi.html` 是 **VISI by RICCIONE REKA** —— 做初步方案（moodboard proposal）与跟进文案的工具，见下面「VISI」。

---

## 三个页面

| 文件 | 给谁 | 做什么 |
|---|---|---|
| `brief.html` | 客户 | 6 组问题的需求卡：联络方式 · 房产 · 定制范围与风格 · 家庭与生活习惯 · 预算与决策 · 到馆时段。填完打开 WhatsApp，内容已经排版好，客户按发送即可。 |
| `index.html` | 客户 | 邀请函。封面写着客人的名字 → 谢谢信 → 关于我们 → 60 分钟流程 → 这场体验会带走什么 → 9 步停车指引 → 结尾。中英双语可切换。 |
| `create.html` | 销售（内部） | 生成上面两条链接 + WhatsApp 文案。已加 `noindex`，但仍建议不要外发。 |
| `visi.html` | 销售（内部） | 贴需求卡 → 自动排好 16:9 的 moodboard（封面 · 开场短话 · 你们说的 · 一页看懂 · 平面图 · 逐个空间 · 到馆邀约 · 欢迎回家）→ 导出 PDF / PPTX；同时写好 6 则文案。 |

## VISI by RICCIONE REKA（`visi.html`）

**网址：<https://visi-riccione-reka.vercel.app>**（同 TORA 的做法：独立的 Vercel 项目，打开就是 VISI）。
手机上「加入主画面」会出现 V 图标与「VISI」。

把「做一份 proposal」从几个小时缩到十分钟。整套在浏览器里跑，没有后端。

**销售的做法**

1. 收到需求卡 → 打开 `visi.html` → **＋ 新方案** → 把 WhatsApp 上的整段需求卡贴进 ①。
   客户名字、楼盘、要做的空间、风格方向、需求、方便到馆的时段，全部自动带出；每个空间自动配好图与卖点。
   （内置图库没有浴室 / 梳妆台 / 神台的照片 —— 这几个空间先到「图库」拖旧 proposal PDF 或上传。示范方案不会被覆盖：在示范上贴需求卡会自动新建一份。）
2. ② 选风格方向（对应溪岸五个系列），配色 / 材质改成真实板材色号。
3. ③ 每个空间换图、勾卖点、写一句「为你」（亲手挑过的图，换风格时不会被洗掉）。④ 上传平面图，点一下放编号。
   ⑤ 确认到馆时段（按需求卡自动建议的时段，要按「已确认留好」）与「为他们准备的三样」。客户回「2」就按「客户选了时段 2」。
4. 右上角 **体检** 全绿（字太多放不下的页会先自动缩小，还放不下体检会提醒；同一张照片用了两次也会提醒）→ **导出 PDF**（打印对话框选「另存为 PDF」，16:9，档名已带客户名）或 **导出 PPTX**（每页附讲稿）。
5. ⑥ 文案：发方案 → 邀约到馆 → 没回跟进 → 到馆前提醒 → 60 秒讲解稿 → AI 润色提示词，复制或一键 WhatsApp。

**页序为什么这样排**（《快思慢想》）：封面就写客户名字（WhatsApp 预览只显示第 1 页）→ 业务署名的开场短话 → 用客户原话的「你们说的 · 我们做的」
→ 一页看懂（先给完整、连贯的感觉）→ 平面图编号 → 每个空间一张主图 + 最多两张辅图 →（参考空间）→ 品牌只占一页 → 已经留好的到馆时段与二维码 → 欢迎回家（峰终定律）。

**图库**

- 内置：`assets/img/cases/` 里溪岸自家的空间照（`assets/js/visi/data.js` 的 `MB.BUILTIN`，`rooms` 决定自动配图配到哪个空间）。
- 自己的图：在「图库」上传，或**把以前做好的 proposal PDF 拖进去** —— 会用 pdf.js 取出原图，按页面标题（FOYER / KITCHEN …）自动分好空间。
- 图库与方案都存在**这台电脑的浏览器（IndexedDB）**，不上传、不进 git。换电脑 / 给同事：图库页的「导出图库」「导出这份方案」存成 `.json`，再导入。
- 这个 repo 是公开的：客户的平面图、名字、网上找的参考图都**不要**放进 `assets/`，留在浏览器图库里就好。

**公司案例库**（`assets/js/visi/cloud.js`，资料来自 `api/catalog?view=visi`）

- 「图库」最上面用**名字 + 团队密码**登入一次。之后图库、选图多一个来源「公司案例」，可以按 风格 × 柜类 × 项目 筛（每页 48 张，用缩图）；
  项目只显示「区域 · 风格 · #n」，**绝不显示文件夹名**（里面有客户的名字）。每张案例有「同项目」看同一个家的其他照片。
- **帮我挑**（图库、③ 参考空间、贴完需求卡都会出现）：按需求卡的区域 / 房型 / 家庭（长辈、小孩、宠物、帮佣）/ 风格 / 要做的柜子，
  从案例库挑 6–9 张，每张附一句只用真的对得上的事实拼成的「为什么」（例：「一样是 Setia Alam 的排屋 · 厨房有中岛 · 同样有长辈同住」）。
  业务按「放进厨房」「放进参考空间」才会用；放进参考空间时，那一句就是说明草稿，可以改。规则在 `model.js` 的 `MB.matchCases`。
- 贴需求卡时，参考空间还空着就先自动挑 3 个不同的家（`MB.suggestCases`）；自动配图也会优先用同风格的案例。
- 清单与缩图存在这台电脑（IndexedDB `sail-visi-cases`），最多 10 分钟问一次有没有更新；离线、API 出错时旧方案的案例照片照样解析得到。
  没登入过的电脑一个请求都不发（静态网站上跟以前一样）。
- 方案里的案例照片存成 `c:<16 码>` 的 ref。**「导出这份方案」的 `.json` 只带 ref、不带照片**：同事导入后要登入公司案例库才看得到那几张图。
- 隐藏的、标了「不确定」的照片不会被自动挑；旧方案已经用了的照样印，但体检会提醒换掉。
- 案例库被 Vercel 暂停（免费额度用完）时，图库显示「公司案例库暂停中」，案例照片先不拿来配图、帮我挑也不挑；
  方案里已经放了的案例照片显示空位，不会出现破图，体检会提醒先别发。内置照片和自己的照片照常用。
  在审核页被删除的案例照片也一样：旧方案里那一格变空位，体检提醒换一张。
- 导出 PPTX：案例照片在 Blob 的网址，要那边开了 CORS 才放得进 PPTX；放不进去时照样导出，并告诉业务有几张没放进去（PDF 不受影响）。

**案例库管理**（`caselib.html`，VISI 图库里「打开案例库管理 →」）

**本机模式：「存在这台电脑」（免费，现在就能用）** —— 云端（Vercel Blob）2026-11-03 被暂停、而且免费方案不能商用，所以先用这个：

- **怎么开**：打开 `caselib.html`，登入框最上面选「**存在这台电脑**」（第一次打开就是选好的），填你的名字，按「开始用」。不用团队密码。
  右上角会写「存在这台电脑」。之后上传、审核、只留最好的 N 张、删除，跟云端一模一样；**没有每月的次数限制**，精选模式预设关着（要的话自己打开）。
- **自动分类**：照片登记进来时，文件夹名的风格（原木、奶油风、轻法式…）和区域（例：`Setia Alam 原木 陈先生` → Setia Alam），
  子文件夹名的空间（厨房、主卧、客厅、浴室、玄关、儿童房…）和柜子（橱柜、衣柜、鞋柜、电视柜、电视墙、中岛、浴室柜…）会**自动标好**（状态「自动标签」）。
  客户名字绝对不会被当成标签：区域只收常见的地名（Setia Alam、Kepong…）或 Taman / Bandar / Desa / Kota… 开头的，
  看不出是地名的（英文名字、楼盘名，例：`M Vertica`）就留空，你在「审核」自己填。以前传的照片按审核页的「**按文件夹名字自动标**」。人改过、确认过的不会被盖掉。
- **资料在哪里**：这台电脑这个浏览器的网站资料里（IndexedDB）。**只用 Chrome 或 Edge**：Safari 只要 7 天没打开这个网址就会把资料清掉（用 Safari 打开会提醒）。所以：
  - **不要清除浏览器的资料**（「清除浏览资料」里的 Cookie 和网站资料），也不要用无痕视窗。
    清掉了，照片可以从文件夹再汇入一次，但**分类会不见**（审核改过的空间、柜子、风格、说明，隐藏、只留最好的 N 张）：
    **请定期在「审核」按「汇出标签档（备份）」**存一份；清掉、换电脑之后，汇入同一个文件夹、再汇入这个档，分类就回来。审核页很久没备份会提醒。
  - 开始用的时候会请浏览器「一直保留」这些资料；浏览器还没答应（硬碟快满时可能被清掉），页面最上面会一直有一行红字提醒你备份。把这个网址加进书签、常常打开，浏览器比较会答应。
  - 换一个浏览器、换一台电脑，那边是空的；同事**看不到**你的照片。上传页和审核页会写「已用约 X / 可用约 Y」。
    电脑的空间满了会自己停下来，说「这台电脑的空间满了」：清出一些硬碟空间、或删除隐藏的照片，再拖一次同一个文件夹。
- **给同事用**（他的电脑也要有一份）：
  1. 把**同一个案例文件夹**给他（随身碟、Google Drive 都可以），他在他的电脑选「存在这台电脑」，把文件夹拖进来。
  2. 你在「审核」按「**汇出标签档（备份）**」（一个 `.json`，只有分类，没有照片、没有档案路径），传给他；他在「审核」按「**汇入标签档**」。
     **档里有项目的文件夹名（就是客户名字）**：只给同事，不要传给客户、也不要放进有外人的群组。
     顺序反过来也可以：先汇入标签档，再汇入文件夹 —— 还没有的照片会先记着，汇入那个文件夹时自动套用，两种顺序结果一样。
     他那边已经确认过的照片只补空着的栏位，不会被盖掉；你改过的项目风格、区域会盖掉他那边从文件夹名自动猜的。
     他用不到的项目（不会汇入那个文件夹）：审核页「还有 N 张照片的标签在等」旁边按「不用等了」。
- **VISI**：同一个网址的 VISI 会自己用这份本机案例库（图库写「本机案例库 · N 张（存在这台电脑）」）；帮我挑、自动配图、PDF、PPTX 都照常。
  同事做的方案用到你电脑上没有的案例照片：方案页印成空白的占位框，体检会说「这台电脑没有（要先汇入那个项目的文件夹）」；
  那几张会留着（自动配图、换风格、重新选图之前会先问），汇入那个文件夹就回来。
  在案例库按了「登出」：VISI 会说「本机案例库登出了（照片都还在）」—— 到案例库填名字、按「开始用」就好，不用再拖文件夹。
- **改回云端**：右上角「改用云端」（登入框上点「云端」只是先看看：要登入成功才会换）。本机的照片和标签都留着，之后按「改用这台电脑」就回来；
  用了本机照片的方案，在云端模式体检会说「是本机案例库的照片：改回『存在这台电脑』就看得到」，那几张不会被换掉。
  照片 id（原档的 sha256）和项目 id（文件夹名算出来的）在两边一模一样：以后搬回云端（例：升级 Vercel Pro），再把文件夹拖一次、汇入标签档，分类都还在。
- 程式：`caselib-sw.js`（service worker，在浏览器里回答同样的 `/api/*`，照片在 `/local-cases/…`；只管 `caselib`、`visi` 两页，
  给客户看的邀请页不会被它管）、`assets/js/caselib/local-core.js`（清单规则，照抄 `api/_lib/catalog.js`，测试逐项比对）、
  `assets/js/caselib/local-sw.js`（切换模式）。测试：`node --test tools/caselib/test/local-core.test.mjs`、`node --test tools/caselib/test/local-mode.mjs`。

**云端模式（Vercel，现在暂停中）**：

- **上传**：用 Windows 的 Chrome，把装案例的**总文件夹**整个拖进来（或按「选文件夹」）。里面每个子文件夹就是一个项目；
  子文件夹里再分「厨房」「主卧」也可以。HEIC、RAW、影片、超过 60MB 的档会列出来跳过（HEIC 请先转成 JPG）。
  照片在浏览器里先缩成 1200px（约 150–250 KB，顺便去掉 EXIF / GPS），20 张登记一次；中途断网、关掉，再拖一次同一个文件夹就从断的地方接着传，传过的不会重传。
- **免费方案的额度**（Vercel Hobby）：每月约 2,000 次写入、储存 **1 GB 总量**（不是每月重算）。超过的话 Vercel 会把整个案例库停权约 30 天，
  连已经传上去的照片都打不开（2026-11-03 传到 2,595 / 9,735 张时发生过）。所以伺服器自己设了上限，到了就回「额度用完」，不写：
  - 传新照片：这个月写入到 **1,800** 次、或总储存量到 **950 MB** 就停；
  - 登记、改标签、隐藏：到 **1,950** 次才停（已经传上去的照片还能登记）；删除到 1,990 次。
  - 上传页开始前会说「这个月还能传约 N 张 · 空间还够约 M 张」，超过的照片先自动不选，下个月再拖同一个文件夹就接着传；没有「照样上传」。
  - **精选模式**「每个项目最多 6 张」（可以改）：同一个镜头只留一张、横的和清楚的优先、分散到不同的子文件夹（空间）、彼此最不像的优先
    （`assets/js/caselib/pick.js`）。项目可以展开，自己勾 / 取消。已经在库里的照片也算在 6 张里；删除过的照片默认不再传。
  - 升级 Vercel Pro 之后，在 Vercel 加环境变数 `BLOB_PLAN=pro` 并重新部署，就没有这些上限。
- **审核**：按 风格 × 柜类 × 空间 × 状态 × 项目 筛；点照片改空间、柜类、风格、能不能当主图；项目填区域、房型、家里有谁。
  改动停手 45 秒（一直在改最多 2 分钟）、按「保存」、切到上传分页或离开这一页时一次存起来，每次都记下是谁改的；
  隐藏 / 复原连按几张会一起送。每次保存都是一次 Blob 写入，审核页右上角显示这个月的写入次数和用了多少空间。
  「隐藏」可以复原，不会真的删掉。**真实的文件夹名（有客户名字）只在这一页出现。**
- **释放空间**（审核页，分两步）：
  1. 「只留最好的 N 张」（单一项目，或每个项目一起）：用跟精选模式同一套挑法，其余的**隐藏**（可以复原）。
  2. 「删除隐藏的照片（释放空间）」：真的删掉 Blob 里的档和清单里的那几笔，**不能复原**。要亲手打「删除」两个字才按得下去，
     纪录里记下是谁删的；删完显示剩下多少空间。只有已经隐藏的照片删得掉。
- **一次性设定（老板）**：
  1. Vercel → Storage → Create → Blob：名字 `visi-cases`、区域 Singapore、**Public**，Connect 到 `visi-riccione-reka`（Production + Preview）。
  2. Vercel → `visi-riccione-reka` → Settings → Environment Variables：加 `VISI_TEAM_PASSWORD`（团队密码，Production + Preview），然后重新部署。
     **密码要长、要随机**（例：四、五个不相干的词加数字，20 个字以上），不要用「Sail2026!」这种好猜的 ——
     网址和登入方式在公开的 repo 里看得到，猜中就看得到所有项目名（客户名字）、改得了所有标签。
     伺服器会挡猜密码：同一个 IP 10 分钟错 5 次、全部加起来错 30 次，就先锁 10 分钟（已登入的人不受影响）。
     有人离职就换密码（换了全员要重新登入）。
  - 已经设好（2026-11-03）：Blob store `visi-cases`（Singapore、Public，连上 Production + Preview，用 OIDC：只有 `BLOB_STORE_ID`）、
    `VISI_TEAM_PASSWORD`、`SESSION_SECRET`（登入签名）、`CATALOG_KEY`（清单的秘密路径）。后两个 Production 与 Preview 各一组随机值，
    所以两边的清单是分开的。**`CATALOG_KEY` 不要改**（改了就找不到原来的清单）；换 `SESSION_SECRET` 或密码只会让大家重新登入。
  - Blob 只有 OIDC（没有 `BLOB_READ_WRITE_TOKEN`）时，Vercel 上缺 `SESSION_SECRET` / `CATALOG_KEY` 会回「not_configured」，不会退回猜得到的 key。
  - 清单每天第一次写入前备份一份，按星期几轮流覆盖（`catalog/<key>/bak/mon.json` …，最多 7 份）。
  - Blob 这个月的额度用完、store 被停用时，上传页会整批停下来并说明原因；已传好的照片记在那台电脑，之后再拖一次同一个文件夹就接着传。
  - **被停权之后怎么办**：到 Vercel → Storage → `visi-cases` 看什么时候恢复（约 30 天；超过还没恢复就找 Vercel 客服）。
    恢复后先在审核页「只留最好的 N 张」→ 检查 →「删除隐藏的照片」，把空间压到 950 MB 以下，再用精选模式传还没传的项目。
- 程式：`api/session.js`（登入）、`api/photo.js`（存照片）、`api/catalog.js`（清单），共用的在 `api/_lib/`；
  测试与本机模拟伺服器在 repo 根目录的 `tools/caselib/`（`node --test tools/caselib/test/`、`node tools/caselib/mock-server.mjs --port 0`）。

**要改的东西都在 `assets/js/visi/data.js`**：空间与卖点（`MB.ROOMS`）、五个风格的配色与材质（`MB.DIRECTIONS`）、
需求卡选项对应的说法（`MB.NEEDS`）、内置图库（`MB.BUILTIN`）。文案写法：标题说「得到什么」，理由用「少一个麻烦」的说法，不编数字。

**二维码**：邀约页的二维码就是邀请函链接，网址取自 `config.js` 的 `publicBase`（邀请函的正式网址）。
所以不管 VISI 在哪里打开（visi-riccione-reka.vercel.app、自己的电脑），客户扫到的都是正式邀请函。

`assets/vendor/` 里是 pdf.js（Apache-2.0，只在导入 PDF 时才载入）与 qrcode-generator（MIT）。

## 文案怎么写（给新同事）

VISI 做的是 **moodboard**：以图为主、字要少。客户只花几秒判断「这是不是为我们做的」，
所以每一句都要具体、真实、跟他们有关。我们用六本书，各管一层，不平均混用。
界面上不标书名；体检只讲「要改什么、为什么」。

1. **骨架 ·《快思慢想》**：一页只讲一件事；先给第一印象，结尾给下一步。
   例：封面第一行就是客户名字（WhatsApp 预览只看得到第 1 页）；最后一页是已经留好的时段，不是电话号码。
2. **说服的点 ·《影响力》七个原则，只用真的**：
   - 互惠：到馆那天为他们准备好的三样。
   - 承诺与一致：引用他们在需求卡写的话；「回我一个页码」「回 1 或 2」。
   - 社会认同：现在的案例页叫「参考空间 · SAIL spaces」—— 放的是溪岸自家的空间照（品牌手册 / 内置图库），不是客户的家，
     所以那一句只写真的知道的事：同系列的写「和你们第 10 页的厨房同一个系列」；不同系列的写那张图拍的是什么（「吧台与储物墙」），
     不重复卡片上已经印的「骨骼线 · 厨房」、也不每张都写「供你们参考」；不写「像你们」「跟你们很接近」。
     等云端案例库有了每个项目的区域、房型、家里有谁，才改回「像你们这样的家」，写「也在 Setia Alam · 也有长辈同住」。
   - 喜好：业务署名的开场短话。
   - 权威：MUSE、HCA、Egger、Blum 压成品牌一页，放在他们的家后面。
   - 稀缺：只写真的，例：「这个时段为你们保留到 11 月 8 日」。按需求卡自动建议、还没确认的时段，讯息只说「建议」「回我 1 或 2 就帮你们留下来」，不说「已经留了」。
   - 联盟：「展厅和你们新家在同一个镇区」（真的同一个镇区才写）。
3. **语气 · 卡耐基《人性的弱点》**：讲他们在乎的事、叫他们的名字、真诚、不批评他们现在的家。
   例：「为 Mr & Mrs Lim」那一句写「你们几乎天天开火，所以锅具放在腰部高度的拉篮」，不写「你们现在的厨房很乱」。
4. **对话 ·《掌控谈话》**：让客户看完心里说「对，就是这样」；先把他们的顾虑讲出来；问句让对方回「不」。
   例：第 2 页先说他们说过的一件事；工期·保障页先写「要等多久？会不会一拖再拖？」再老实回答（不保证不会延期，只说真的会做的：每天在群里汇报）；
   跟进讯息结尾是「这个时间会不会太赶？」，不是「方便吗？」。
5. **底线 · 稻盛和夫**：每一句都要是真的。数字只用公司资料（`brand.js`：订单周期 60–75 / 75–90 天、五金终身保家、板材 1 年）和你填的真实资料。
   不编折扣、期限、案例、奖项。例：体检看到「限时」「名额有限」「last chance」会标红。
   - **引号只给客户自己打的字**。需求卡上勾选的选项不是他们说的话，开场短话、「你们说的」页、讯息、讲稿都用转述：
     「你们提到家里有长辈同住」，不写「你们说『长辈和我们同住』」。（`copy.js` 的 `MB.needSaid` 给「你们说的」页用同一套说法）
   - **不说没做到的范围**：只做一两个空间的方案，英文不写 whole home（华文「全屋定制」是服务的名字，照用）。
   - **AI 润色提示词**也给「我们的做法」：只能用写好的做法和页码，还没有做法的就说「见面一起想」，不让 AI 替我们编。
   - **不答应方案里没有的东西**：需求对应的空间不在方案里（例：鞋子多，但没有做玄关），开场短话不会拿它来回答，体检会提醒。
   - **不替材料打包票**：写 moisture-resistant（防潮板 + 封边），不写 moisture-proof，也不写没有根据的「湿区规格」；
     展厅能不能在日光下看、样板有没有，都要先确认再写。
6. **具体 ·《让创意更有黏性》**：看得见、摸得到的细节，胜过形容词。
   例：写「抽屉拉出来的分量、柜门关上的那一声」；不写温馨、高端、奢华、完美、cozy、premium（体检会提醒）。

**字数上限**（华文字 / 英文词，双语时各自都要守）。页面上放不下的细节，写进讲稿（每页的 PPTX 备注），当面讲：

| 哪里 | 上限 |
|---|---|
| 第 2 页开场短话 | 70 字 / 55 words（两三句） |
| 需求：他们的原话 · 我们的做法 | 20 / 12 · 30 / 18 |
| 空间页：一句 head · 卖点名称 ·「为 X」 | 18 / 10 · 8 / 4 · 40 / 25 |
| 到馆准备的每一样 · 案例那一句 · 风格 mood | 16 / 9 · 20 / 12 · 24 / 14 |

**开场短话**：VISI 会先起草：他们说过的一件事 → 这份方案在第几页怎么回应 →「慢慢看，想改的地方圈起来，见面一起过一遍」。
这一页不约时间（邀约页和 WhatsApp 已经在约了）；风格与配色在「一页看懂」，有做法可讲时不再重复。
双语方案：华文一段先挑（客户自己写的优先），英文一段讲同一件事；英文引不了华文原话时，就写「The kitchen you told us about is on page 10.」。
WhatsApp「发方案」与 60 秒讲解稿引用的，也是同一件事。
草稿只用得到需求卡上的字 —— 请加一件只有你知道的事（见面时他们提过的一个细节），体检才会过。

**讲稿**（PPTX 每页的备注）：要念得出来 —— 句中不用大写、不用「 · 」。页面上没印的东西都在这里：卖点的理由、多勾的卖点、没印出来的需求、三句承诺、订单周期与售后的细节。

**体检只讲要改什么**（不讲书名、不讲术语）。除了空话、假急迫、太长，还会提醒：
需求超过 3 条（列出没印的是哪几条）、卖点超过 3 个、需求是空的、需求对应的空间不在方案里、
同一张照片在方案里出现两次（含同一张的不同裁切）、两张照片拍的是同一个地方、主图和方案风格不一样、
没有实景图的空间先放了质感照代替（页面不空白，但要换上实景）、开场短话还是自动草稿、
哪一页字太多放不下（含邀约页的「为你们准备好的」、工期页「你们家 / 预算」那一行）。

**称呼一致**：华文的讯息、讲稿跟方案页同一个称呼（「Wong 先生、太太」），不会 PDF 一个叫法、WhatsApp 另一个。

**要改文案去哪里**：卖点、需求做法（含勾选项的转述 `told`）、风格、常见顾虑在 `assets/js/visi/data.js`（`MB.ROOMS` / `MB.NEEDS` / `MB.DIRECTIONS` / `MB.CONCERNS`）；
讯息、开场短话、案例那一句、每页讲稿在 `copy.js`；体检规则在 `check.js`。

## 怎么用（销售）

1. 打开 `create.html`，第一次填一下「我是谁」（姓名 / 职称 / WhatsApp），浏览器会记住。
2. **刚聊上客户** → 填客户称呼和他的 WhatsApp → 复制①的文案，或直接点「用 WhatsApp 发送」。
3. **客户填完需求卡**，内容会以文字形式发到你的 WhatsApp。读完，做一版初步方案。
4. **约好时间之后** → 回到 `create.html` 填日期时间，在「给客户的一句话」里写下邀请的理由
   （例：「您提到厨房永远收不干净 —— 我们照着您的平面图画了三种做法」）→ 发②邀请函。

> 那一句话会印在邀请信里。有理由的邀请，和「欢迎参观」是两件事。

## 配置

只需要改 `assets/js/config.js`：

```js
host:       { name, role, wa }   // 默认邀请人（链接没带参数时用）
briefInbox: '60189661919'        // 需求卡送到哪个 WhatsApp
venue:      { address, hours, phone }
team:       [...]                // 团队成员
briefEndpoint: ''                // 选填，见下
```

### 需求卡要不要存进数据库

默认只走 WhatsApp（客户按发送，你在手机上收到文字）。
想同时存一份，把 `briefEndpoint` 填上任何接受 JSON POST 的地址即可 ——
Formspree、Supabase Edge Function、Google Apps Script 都行。送出时会 POST：

```json
{ "host": "Wilson Teo", "submittedAt": "…", "text": "整段文字", "data": { "name": "…", "budget": "…" } }
```

失败不会打断客户，WhatsApp 那条路照走。

## 链接参数

**邀请函** —— 由 `create.html` 生成。参数都是可读的短词，链接里不会出现电话号码、
中文乱码（`%E5%A5%B3%E5%A3%AB` 那种），也不会有 base64：

```
/invite?for=Peggy&title=ms&on=2026-08-26
```

| 参数 | 意思 | 例 |
|---|---|---|
| `for` | 客人称呼 | `Peggy` |
| `title` | 称谓代号 | `mr` `ms` `mrs` `miss` `teacher` `designer`（直接写中文也认） |
| `on` `at` | 日期 · 时间 | `2026-08-26` `15:00`（14:00 是默认值，会省略） |
| `mins` | 时长，默认 60 | `90` |
| `from` | 邀请人代号，取自 `config.js` 的 `team[].code` | `wilson` |
| `note` | 印在信里的那一句话（勾选才会带上） | |
| `open=1` | 跳过封面动画，预览用 | |

**需求卡** `/invite/brief?from=wilson&for=Peggy`

`from` 决定填完之后送到谁的 WhatsApp。名单在 `config.js` 的 `team`，
不在名单里的人会自动退回 `by=姓名&wa=号码` 的长格式 —— 所以新同事记得加一行。

旧的短参数（`n` `t` `d` `h` `by` `wa` `msg`）和 `?i=<base64>` 都还认得，发出去的旧链接不会失效。

## 部署

整个 `invite/` 由 Vercel 项目 **`visi-riccione-reka`** 部署：Root Directory = `invite`，Framework = Other，
没有 Build Command；开了「Skip unaffected projects」与 Ignored Build Step `git diff --quiet HEAD^ HEAD -- .`
—— `invite/` 没改就不部署，省每天 100 次的部署额度。同一份部署挂两个网址：

```
https://journey-riccione-reka.vercel.app/?for=Mr%20Tan&on=2026-08-25   邀请函（发给客户）
https://journey-riccione-reka.vercel.app/brief                         需求卡（发给客户）
https://journey-riccione-reka.vercel.app/create                        销售端
https://visi-riccione-reka.vercel.app                                  VISI（首页直接打开）
```

`invite/middleware.js`（Vercel Routing Middleware）只在 `visi-riccione-reka.vercel.app` 的首页 `/` 生效：那个网址的首页是 VISI；
其它网址（journey）的首页仍然是邀请函。（不用 `vercel.json` 的 rewrites：首页已有 `index.html`，Vercel 会先给档案。）
`cleanUrls` 已开，路径里不会出现 `.html`。

> 因为 VISI 的网址首页就是 VISI，客户的链接**不能**用这个网址 —— 所以 `create.js` 与 VISI 生成链接时都用
> `config.js` 的 `publicBase`（现在是 `https://journey-riccione-reka.vercel.app`）。换邀请函的域名，只改这一行。
> 邀请函与需求卡的 `og:image` 也写成这个网址的绝对路径，WhatsApp 预览才会出图。

**旧网址：** 以前邀请函挂在根目录项目 `wilson-pidc` 底下（`wilson-pidc.vercel.app/invite/…`，build 时把 `invite/`
复制进 `dist/invite/`）。根目录 `vercel.json` 已设 `git.deploymentEnabled: false`：`wilson-pidc` 不再自动部署、
不再占额度，但最后一版仍在线 —— 已经发出去的旧邀请函链接和首页的 Delivery OS 都还打得开，只是不会再更新。

有自己的域名之后，在 Vercel 的 Domains 里接上去（例如 `journey.riccione.com.my`），再把 `publicBase` 改成它。

其它选择：Netlify（publish directory 填 `invite`）、GitHub Pages、自己的服务器 —— 整个目录丢进去就行。

本地预览：

```bash
cd invite && python3 -m http.server 8899
# 打开 http://localhost:8899/create.html
```

部署后记得在 `index.html` 里把 `og:image` 换成绝对网址，WhatsApp 的链接预览才会出图。

## 换作品 / 案例

邀请函「关于我们」里的五个系列是可以点开的 —— 点一下打开灯箱，左右翻看，手机上可以滑动。

**现在放的是公司手册里各系列的空间实例，不是马来西亚的真实交付案例。**
等你们有客户家的实拍照，换掉会更有说服力。做法：

1. 把照片放进 `assets/img/cases/`（宽度 1000px、JPEG 质量 ~76 就够）
2. 打开 `assets/js/cases.js`，改 `window.SAIL_CASES` 这个数组：

```js
{
  slug: 'skeleton',                     // 随便取，只要不重复
  zh: '骨骼线', en: 'Skeleton Line',     // 卡片标题
  tagZh: '古典与现代的对话', tagEn: '…',  // 标题下那行小字
  descZh: '…', descEn: '…',
  photos: [
    { src: 'skeleton-1.jpg', zh: '主卧 · 通顶衣柜与过道', en: '…' },   // 第一张是封面
    …                                                                // 想放几张放几张
  ]
}
```

系列本身也可以整组换成「XX 花园 · 三房单位」这类真实案例 —— 结构一样，卡片数量自动跟着数组走。
