## 1. 产品目的 + V-SMOOTH 方法论

### 一句话
> SAIL Delivery OS 是溪岸马来西亚全屋定制业务的**交付管理操作系统**。
> 每一个客户从签约到入住的全程, 走同一套 6 章节 + Gate 检查表 + 表单 + 日报的方法。
> 目的: 让 SD / SS / WH / PU 四个岗位在同一份流程上协作, 每一步都留痕、都可追责、都对客户透明。

### V-SMOOTH 六章节
每个项目按顺序流经这 6 个章节。每章节有若干 **Gate (检查点)**, 所有 Gate 打勾才算完成该章节。

| 章节 | 代号 | 主理 | 典型周期 | 含义 |
|---|---|---|---|---|
| **V** ision | 洞察 | SD 销售设计 | 销售前 | 客户洞察、建立信任、收定金 |
| **S** tart | 启动 | SD 销售设计 | 1-2 周 | 项目启动、量尺、签图、下单 |
| **M** ake | 匠造 | PU 采购 | 4-8 周 | 生产监控、客户透明 |
| **O** nsite | 就位 | SS 现场主管 | 3-7 天 | 到货核查、现场就绪 |
| **T** ackle | 安装 | SS 现场主管 | 1-2 周 | 现场安装、每日跟踪 |
| **H** andover | 交付 | SS 现场主管 | 1-2 天 | 验收、交付、长期关系 |

### 核心承诺
> 「We don't ship until each gate is closed.」
>
> 每一道 Gate 关上, 才有下一步。这是 SAIL 的纪律。

**IT 必须理解**: V-SMOOTH 不是任意分类, 是**销售流程**。改章节顺序 / 改数量 / 改代号 = 破坏了公司在用的语言。**不能改**。

## 2. 迁移原则

### ✅ 必须保留（保留原样）
1. **V-SMOOTH 6 章节**代号 + 名称 + 顺序
2. **所有 Gate 的代号 + 描述**（V1, V2 ... H5, 见 §3.2）
3. **5 份核查表**的所有题目, 每题的选项和类型 (见 §4)
4. **业务规则**（Stage Gate 签字要求、4 项安全检查、设计 SLA、见 §5）
5. 客户资料字段（客户名、地址、电话、微信、决策人、来源等）
6. 岗位分工（SD / SS / WH / PU）

### 🔄 可以放弃 / 用 Lark 替代
- 品牌视觉（Fraunces 字体、溪岸配色、罗马数字排版）→ Lark 通用样式即可
- 自建的中英切换 → Lark 有原生多语言
- 自建的登录 → Lark 通讯录 + 权限
- 自建的文件上传 → 直接放 Google Drive / Lark 云文档链接
- 自建的日历 → Lark Calendar
- 自建的群通知 → Lark 群机器人
- 自建的审计 log → Lark Base 自动带修改记录

### ❌ 不能破坏 / 优先级最高
- **Stage Gate 签字门**: S3 (图纸客户签核) 和 H1 (最终验收表) 必须要求填 Drive 链接才能打勾, 不能省略
- **4 项安全检查**: 水阀 / 总电源 / 门窗 / 现场清理 —— 每天日报强制填, 不允许有一项不勾就提交
- **设计流程按报价分级 SLA** —— 见 §5.3

## 4. 5 份核查表完整题目

用 **Lark Forms** 一份一张, 提交后自动进对应 Base 表。

### 4.1 客户空间问卷 SPACE_SURVEY (28 题)

**用途**: 销售前理解客户生活方式, 决定方案方向 (V3 Gate 依据)。**客户自己填 + SD 引导**。

**入户** (4 题):
- 鞋子总数预估 [单选: <30 双 / 30-50 双 / >50 双 / 有 >43 码或长靴]
- 随手区 + 仪容镜 [是/否]
- 大件物品收纳 (行李/婴儿车) [是/否]
- 神台/地主公位置 [是/否]

**客厅** (4 题):
- 视听设置 [单选: 整面电视柜 / 简约悬空柜 / 投影+矮柜 / 其他]
- 展示需求 (艺术品/手办) [是/否]
- 隐藏扫地机器人 [是/否]
- 柜体风格 [单选: 全柜门 / 开放格 / 玻璃门 / 露二藏八]

**餐厨** (6 题):
- 餐边柜 + 备餐台 [是/否]
- 酒柜/茶柜/小家电 [单选: 仅酒 / 仅茶 / 小家电为主 / 混合 / 不需要]
- 净水机 [单选: 台式 (Coway) / 立式 (Cuckoo) / 其他 / 不需要]
- 厨房布局 [单选: U 形 / L 形 / 一字 / Galley+中岛]
- 封闭 vs 开放 [单选: 封闭 / 开放 / 半开放]

**卧室** (6 题):

**卫生间** (3 题):

**多功能 + 阳台** (4 题):
- 多功能房功能 [单选: 书房 / 客房 / 茶室 / 电竞 / 储物 / 混合]

**门板与抽屉** (5): 门缝均匀 ≤2mm / 铰链紧固 / 滑轨顺滑 / 软关闭正常 / 把手牢固 [全 是/否]
**五金件** (3): 拉篮/旋转架 / LED 全亮 / 升降拉杆气撑 [全 是/否]
**台面与饰面** (4): 无划痕 / 接缝无渗胶 / 无气泡脱胶 / 收边平整 [全 是/否]
**电器与现场** (4): 嵌入电器到位 / 燃气电连接 / 现场清理 [是/否] + 未完成事项 [长文本]

### 4.5 最终验收表 HANDOVER (16 题)

**用途**: H1 Gate 依据 (签字门)。客户签字后正式交付。

**整体验收** (3): 外观符合方案 / 色彩匹配 / 尺寸比例
**功能测试** (3): 抽屉门开合 / 灯具点亮 / 电器测试
**细节验收** (3): 无瑕疵 / 缝隙均匀 / 五金紧固
**文档移交** (3): 保养说明书 / 保修卡 / 电器说明书
**客户签字** (4): 使用讲解 / 售后联系方式 / **客户签字验收 (照片存档)** / 客户反馈

## 5. 业务规则清单 (硬规则)

### 5.1 Stage Gate 签字门

**S3「图纸客户签核」** 和 **H1「最终验收表」** 这两个 Gate 打勾时:
- 必须弹出确认框, 让用户勾选 "客户已签字"
- 必须填 Drive 链接 (签字文档 / 验收照片)
- 链接自动作为该 Gate 的附件保存

**Lark 实现**: 用 **Approval (审批流)** 或字段依赖 —— 复选框「已完成」勾上时, Drive 链接字段变必填。

### 5.2 4 项安全检查 (每日日报)

日报表单里的 4 项 (水/电/门窗/清理) **必须全部勾选才允许提交**。任何一项未勾 → 提交时报错。

日报总览视图: 未全勾的用红色高亮, 触发早会讨论。

### 5.3 设计流程 6 步 + SLA (Stage S 阶段)

**六步顺序**: 现场量尺 → 方案×技术对接会 → 出效果图 → 方案设计师审查 → (需要则修改) → 内部审查

**工作日 SLA** (周六周日跳过):
| 步骤 | 时限 | 负责人 |
|---|---|---|
| 现场量尺 | 2 wd | 方案设计师 |
| 方案×技术对接 | 1 wd | 双方设计师 |
| 出效果图 | **按报价分级** (见下表) | 技术设计师 |
| 方案设计师审查 | 1 wd | 方案设计师 |
| 修改 (如需要) | 1 wd | 技术设计师 |
| 内部审查 | 客户演示前 ≥2 wd | 方案设计师 + 管理层 |

**出图 SLA 分级** (按报价):
| 报价 | SLA | 客户演示次数上限 |
|---|---|---|
| < RM 100k | 2 wd | 2 次 |
| RM 100k – 200k | 5 wd | 3 次 |
| RM 200k – 500k | 7 wd | 4 次 |
| > RM 500k | 7+ wd | 4 次 |

**关键约束**: 内部审查必须**在客户演示前至少 2 个工作日**完成。演示日期加进去后, 系统自动倒推内部审查截止日期。

**Lark 实现**: 用 Anycross 编写自动化 —— 触发条件是「步骤状态变更」, 动作是「计算下一步截止日 = 今天 + N 工作日」。

### 5.4 缺陷 4 态工作流

`open` → `ordered` → `arrived` → `closed`

- 每次状态变化都要写入历史备注
- `arrived` 状态在早会日报高亮 (「待复装」)
- `closed` 需要填「解决说明」

### 5.5 售后 Drive 强制

售后工单标记为 `resolved` 时, **必须**填 Drive 链接 (签字售后单 + 处理照片)。

### 5.6 演示次数硬阻止

客户演示次数达到报价分级上限时, 不允许再添加。

## 7. 用户角色 + 权限

Lark Base 的**「协作与分享」** → 「按角色配置权限」。

| 角色 | 通讯录部门 | 可见数据 | 可编辑数据 |

| **现场主管** SS | 现场主管部 | 已下单的项目 (Stage M 及以后) | 自己负责的 Daily Reports + Defects + Install QC + Handover |
| **仓储** WH | 仓储部 | 已下单的项目 | Onsite (O) 相关字段 |
| **采购** PU | 采购部 | 已下单的项目 | Make (M) 相关字段, PO 编号 |

**Lark Base 权限做法**:
- 表级权限: 「Space Survey」表 SS/WH 不可见
- 记录级权限: 「Projects」表用筛选 —— 只显示 `SD负责人 = 当前用户` 或 `SS负责人 = 当前用户`
- 字段级权限: 「报价金额」字段对 WH 不可见 (可选)
