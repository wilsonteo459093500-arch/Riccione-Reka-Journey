## 做得好的（不要动）

- **价格表有锁**：改到价格，测试就不过（`vendor.test`、黄金值）。价格表本身和旧工具一字不差。
- **AI 只给建议**：紫色虚线 + 勾选清单，按「加入报价」才算数；AI 读到的比例也要按一下才采用。
- **AI 反馈回路是通的**：👎 → 存云端 → 变成测试资料 → 每次重跑。
- **AI 的钥匙只在服务器**，正式版要登录才能用，没有外人能刷额度。
- **离线、同步想得很细**（待同步、离线删除、多标签页、本机空间满）。
- **Excel 套件的已知漏洞碰不到**：KIRA 只用它导出，不读入外来的 Excel。
- 报价单有条款和有效期；对客户一律印 SAIL BY RICCIONE REKA。

## 要处理的问题

### 高

**1. GitHub 仓库是公开的，价格表、设计师折扣规则谁都看得到**
- 影响：同行、客人上网就能看到每个系列的单价和「设计师 30% + 10%」这类规则，还有公司内部文件。
- 建议：改成不公开（老板已选，2026-11-19）。**要和 Claude 在同一个对话里做**，改完当场验证预览和正式版还能更新 —— Vercel 免费方案对不公开的仓库有限制，Claude 提交的预览版有可能被挡；被挡的话再决定升级方案还是换提交方式。
- 注意：已经公开过一段时间，改了只能挡以后。
- 工作量：小。正式版：有。

**2. AI 识图加进来的柜子，一律按 2.70 米楼高算，不管这间房实际多高**
- 查证：同一个衣柜（宽 1.45 米），房间楼高填 3.0 米。手动加 = RM 8,912；AI 建议加进来 = RM 8,020。**少报 10%**。原因是 AI 那条路没有把房间楼高带过去（`PlanBoard.jsx` 第 206 行）。
- 影响：楼高不是 2.70 的房子，AI 加的顶天柜全部报少（或报多）。你的目标是差 10% 以内，这一条就吃掉了全部。
- 建议：AI 建议加入报价时照房间的楼高重算；加一个测试。
- 工作量：小。正式版：有。

**3. 没有人在用**
- 影响：再好的功能没人用就是零。老板说卡在「还没交给业务」和「不放心价钱」。
- 建议：阶段 3 用 5–10 个真实案子对一次价，出一张老板看得懂的对照表；阶段 4 正式交给业务。

### 中

**4. 设计师净价版 Excel：岩板台面那几行印的是打折后的价钱，但小计是按不打折算的**（只在还没上线的 PR #75）
- 查证：厨房那一区，逐行加起来 RM 19,359，小计印 RM 20,804，差 RM 1,445 —— 刚好是岩板 4.88 延米 ×（800 − 504）。总价是对的（岩板不打折），是**那几行的单价印错**（印 RM 504 / 延米，应该是 RM 800）。
- 影响：设计师拿到的 Excel 自己加一遍对不上，会来问；也可能以为岩板有折扣。
- 建议：上线前修；PDF 净价版一起查。
- 工作量：小。正式版：没有。

**5. 上线流程绕，容易出错**
- 现在：正式版从一条长期分支构建；合并 PR 不会更新正式网址，要另外手动触发；KIRA 不在 main；别的软件的分支一推，KIRA 的 Vercel 项目就多一次失败的构建（最近 8 次都是这样，不影响正式版，但真的失败时会被淹没）。
- 建议：把 KIRA 合进 main，正式版改成从 main 出，合并 = 上线；修掉误构建。
- 工作量：中。

**6. 文档说「和旧报价工具同一个资料库、同一套登录」，实际不是**
- 查证：正式版接的是 11 月 10 日新开的 Supabase 项目，里面没有旧工具的报价表。所以「导入旧报价」在正式版导不到东西。
- 影响：照文档以为旧报价搬得过来，其实不行。
- 建议：改文档；要搬旧报价就另外做（看阶段 3 对价时需不需要）。
- 工作量：小。

**7. 资料没有备份，也没有「谁改了什么」的记录**
- 现在：每个登录的同事都能看、能改所有报价（只有删除限本人）。两个人同时改同一份，后存的盖掉先存的，没有提醒，也找不回前一版。没有一键导出全部。
- 另外：Supabase 免费方案的项目一段时间没人用会被暂停（资料还在，但要手动恢复）。KIRA 现在用得少，有可能遇到。
- 建议：交给业务之前加「每天自动备份 + 改动记录」；两个账号时风险小，人多了就要有。
- 工作量：中。

**8. AI 读到的比例没有合理性检查**
- 查证：比例差 15%，整屋报价就从 RM 55,852 变成 RM 62,487（多 11.9%）。程序只检查「大于 100 毫米、两点相距 20 像素以上」，读成 90 米也收。
- 现在有人按一下才采用，所以还好；做「AI 一键报价」时这一步没人看了，就必须有保险。
- 建议：读到的比例换算成整间屋的大小，不合理（例：卧室 12 米宽）就不采用、请业务量一道墙。
- 工作量：小。

### 低

**9. 折扣可以填超过 100% 或负数**
- 查证：折扣 150% → 总价变成负 RM 2,817；折扣 −10% → 变成加价。输入框没有限制。旧工具也一样。
- 另外：任何业务可以打任何折扣，没有上限、不用批准。这是不是问题由老板定。
- 建议：限制在 0–100%；要不要设上限，交给业务前决定。

**10. 零售版 Excel 逐行加起来和总价差 RM 1–2**
- 原因：每行先四舍五入再加，和总价先加再四舍五入不同。金额很小，但客人自己加会发现。

**11. Supabase 的两个安全提醒**
- 「泄漏密码检查」没开（在 Supabase 后台点一下就好）；一个资料库函数的设定可以收紧。

**12. 没有自动检查**
- 测试很多，但要有人记得跑。合进 main 时顺手加上「每次提交自动跑测试」。

## 没查完的线索（不要当成结论）

- 计算函数本身不挡奇怪的输入（长度打成毫米「2400」会算出一千万）。README 说画面上有防呆，这次没有在画面上逐一试。
- AI 接口等 55 秒、失败重试 1 次，但服务器最多只给 60 秒 —— 重试那一次多半来不及。
- `check-vendor` 说 5 个文件和登记的指纹不同。价格表本身没变（有测试锁），看起来是界面文件有意改过，没有逐个确认。
- 旧报价工具现在放在哪里、业务怎么打开，没查到（Vercel 上没看到它的正常版本）。
- 手机版面、用词、新人引导，没有用眼睛逐页看。
- 没查：柜体画法（立面图 / 3D）对不对、同步在真实断网下的表现。

## AI 自动报价可行吗

**结论：分三层。「业务助手」现在就能做；「客人自助估价」验证过准确度之后可以做；「全自动把正式报价发给客人」不建议当目标，但可以做到「全自动回一个预算范围」。**

### 已经有的积木

1. 看图：AI 读户型图，认出房间、门、窗，每间房建议一套柜子（每次约 US$0.10）。
2. 规则：把 AI 的线变成标准柜子（长度对齐、避开门窗、卧室先留床位、鞋柜一定有）。
3. 算钱：柜子 → 明细 → 总价，完全是程序算的，不靠 AI，有测试锁住。
4. 出单：PDF、长图、WhatsApp、Excel，A / B / C 三档并排。
5. 改进：👎 反馈会变成测试。

一个重点：**价钱看的是「哪间房放什么柜 + 多长」，不是柜子放在墙的哪个位置。** AI 位置放歪一点不影响价钱，长度和楼高才影响。所以「AI 估价」比「AI 摆柜子」容易做准。

### 还缺什么

| 缺的 | 为什么重要 |
|---|---|
| 可靠的比例 | 差 15% 价钱就差 12%。图上有印尺寸才读得到；没有就要有人给一个长度 |
| 楼高 | 现在 AI 那条路不管楼高（问题 2） |
| 系列和材料 | AI 不知道客人要哪一档 → 一律出 A / B / C 三档让人选 |
| 准不准的数字 | 现在没人知道 AI 报的和签约价差多少。要拿真实案子考一次 |
| 给客人用的入口、防滥用、每月花费上限 | 「客人自助」才需要 |

### 分几步走

| 步 | 做什么 | 过了才走下一步 |
|---|---|---|
| A. 业务助手（阶段 2） | 业务上传户型图 → 一键出整屋报价草稿（三档总价）+ 一张「请确认」清单（比例、楼高、每间房柜子长度）→ 业务确认才出单 | 业务愿意用 |
| B. 考试（阶段 3） | 5–10 个成交过的案子：AI 一键报的 vs 签约价，看差多少、差在哪 | 大部分案子在 10% 以内 |
| C. 客人自助估价（阶段 5） | 客人在网页上传户型图、留 WhatsApp → 马上看到**预算范围**（不是正式报价）→ 变成一条线索给业务，业务确认后才发正式报价 | 上线后 AI 估的和业务改完的，连续几周多数在 10% 以内 |
| D. 自动回客人 | 只对「把握高」的案子（图上有尺寸、常见格局）自动回预算范围；其余照旧有人看 | 看 C 的数字再决定 |

正式报价（客人拿来签约的）建议永远有人按一下：最后的价钱本来就要量尺才定，而且这是你自己定的原则「AI 只能建议」。

### 花费

- 每张户型图约 US$0.10。一个月 300 张 ≈ US$30。
- A、B 不用新的系统，是现有 AI 识图的加强。C 要一个对外的页面和防滥用，是比较大的一个阶段。
