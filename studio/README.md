# CIPTA STUDIO · by RICCIONE REKA

内容工作台 —— **构思 / 剪辑 / 发布** 一条龙。

> 核心用法：**上传一条你想要那种感觉的参考视频 + 你自己的原片和案例图 → 拿到一条可以直接去渲染的剪辑方案。**

调研过程和四条渲染流水线的对比见 [`RESEARCH.md`](./RESEARCH.md)。

---

## 它解决什么

你看到一条爆款视频，心想「我也想拍这种」。然后卡住 —— 因为「那种感觉」是一堆说不出口的东西：
第几秒切、字幕几个字一跳、调色偏哪边、钩子在哪一帧。

Studio 把这些拆出来变成可执行的东西：

| | 干什么 | 出什么 |
|---|---|---|
| **构思** | 拆参考视频 | 配方：结构骨架、逐拍时间码、节奏、调色、字幕规律、**素材购物清单** |
| **剪辑** | 配方 × 你的素材 | 时间轴（精确到第几秒切进切出）、缺口清单、`edl.json`、`master.srt`、分镜表、交接指令 |
| **量产** | 一套素材 | N 条互不重复的内容 + 4 周排期 + 自动体检 —— 一次拍摄，一个月的内容 |
| **发布** | 打包 | 5 条不同角度的标题、正文、标签、封面（可直接出图）、第一条评论、跨平台改写 |
| **趋势** | 选题 | 「今天最红什么」实时按钮（带真实链接）、格式雷达、红海/盲区、能开工的选题、内容日历 |

**实拍视频它不渲染**，它想清楚怎么剪，然后把方案翻译成
[剪映专业版](https://www.capcut.cn/)的操作单，或 [video-use](https://github.com/browser-use/video-use) /
[Vyra](https://vyra.ai) 吃得下的格式。这是刻意的分工：浏览器不适合跑 ffmpeg，但非常适合做判断和给你看。

**动态图文帖是例外** —— 那条线不需要素材，动效在浏览器里用 [anime.js](https://animejs.com) 直接播，
导出的 HTML 用原生 Web Animations API 逐帧渲染。看到的就是渲出来的（见下文「动效」）。

## 一条完整的路

1. **构思** — 选平台 → 传参考视频 → 「拆解」
   拿到配方和素材清单。清单每一条都是可执行的拍摄简报（「手持，从关着的柜门推近到 30cm，按下反弹器，2 秒，顺光」）。
2. **剪辑** — 把手上的原片和案例图拖进来
   每条素材先过一遍 AI：里面是什么、哪几秒能用、有什么毛病。然后「排剪辑」。
3. **看一遍** — 点「走一遍」
   用你真实的素材按时间轴顺序播一遍。节奏不对当场就能看出来，省掉一整轮真渲染。
4. **出片** — 下载 `edl.json` + `master.srt`，复制交接指令，在素材目录开 Claude Code 粘贴
   （或者复制 Vyra 指令，在浏览器里让 Claude 直接搭时间线。）
5. **发布** — 生成对应平台的发布包，封面可以直接出图。

## 参考视频是怎么被「看懂」的

| 情况 | 走哪条路 | 能不能听到声音 |
|---|---|---|
| < 14MB | 整条视频内联给模型 | ✅ 有声音，转写 + 音乐能量都能分析 |
| ≥ 14MB | 先试 Files API 断点上传 | ✅ 同上 |
| 上传通道被 CORS 挡住 | **本机抽 18 帧**分析 | ❌ 声音相关的判断会标「推测：」 |

三条路都**不会把原片传到我们的服务器** —— 要么直连 Google，要么根本没离开你的浏览器。

## 数据放哪

- **API key** — 只在本机 `localStorage`，直连 `generativelanguage.googleapis.com`，不过任何中间服务器
- **项目存档** — 本机 IndexedDB，存的是「脑子」（配方 / 方案 / 文案 / 素材元数据 + 缩略图）
- **原始视频** — **不存**。几百 MB 塞进 IndexedDB 只会把浏览器拖垮。重开项目后把原文件再拖进来即可继续预览和导出。

登录用的是和「溪岸 Render」同一套账号密码。

## 量产：一次拍摄，一个月的内容

这一屏的前提是个行业事实：**拍摄很贵，发布很便宜。** 专业账号不是每天在拍，是每天在切。
工具原本假设「一次使用 = 一条视频」，那个假设是最大的产能瓶颈。

它不是把长片切段，是从素材池里找出几个**各自成立的观点**。六条硬规矩写进 prompt，
但**「说清楚」和「保证做到」是两件事** —— 所以 `services/matrix.js` 用代码复算一遍：

| 体检项 | 级别 | 为什么 |
| --- | --- | --- |
| 两条内容开场镜头撞了（同素材且相隔 <2s） | ✗ 硬伤 | 前 1.5 秒决定一切，第二条就是隐形的 |
| 引用的时间段超出素材总时长 | ✗ 硬伤 | 剪的时候才发现，返工 |
| 引用了不存在的素材 id | ✗ 硬伤 | |
| 形式种类 < 4 | ✗ 硬伤 | 连续同一种节奏，第三条就划走了 |
| 观点写成「案例展示」这种筐 | ! 建议 | 一条只能讲一件事 |
| 时间段落在标注的可用片段之外 | ! 建议 | 可能是模型记错，剪前看一眼 |
| 一条素材被 >2 条内容使用 | ! 建议 | 观众认得出同一个画面 |
| 有素材一次都没用上 | ! 建议 | 要么真不能用，要么漏了一个选题 |

排期会把「周三」这种说法落成真实日期，每条内容都能一键带回「构思」继续做。

## 动效：一份 spec，两个渲染端

动态图文帖那条线（`services/motion.js`）把分镜脚本编译成一份**纯数据的时间轴**——
每个元素在第几秒、从什么状态、到什么状态、走哪条缓动曲线。然后两边各自去播：

| | 引擎 | 用途 |
| --- | --- | --- |
| 网站里的预览 | [anime.js](https://animejs.com) v4 timeline | 拖进度条逐帧看，改完立刻知道对不对 |
| 导出的 HTML | 浏览器原生 Web Animations API | 零依赖、可离线、`?t=1.234` 精确停帧 |

**为什么要这么绕**：以前预览是一份手写 CSS 动画、导出是另一份手写 CSS 动画，
改一边忘另一边就会飘。现在两边读同一份 spec —— 已用 Playwright 逐帧比对过
9 个时刻共 95 个元素状态，**两个引擎输出完全一致**。

导出的 HTML 有三种用法：

```bash
# 1. 双击打开就自动播（想看效果）
# 2. 逐帧渲染成 MP4（最准，不掉帧）
npx playwright screenshot --viewport-size=1080,1920 \
  "file://$PWD/post.html?t=0.033" frame_0001.png     # 循环每一帧
ffmpeg -framerate 30 -i frame_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 out.mp4
# 3. npx hyperframes render
```

写关键帧时有两个坑，都踩过了，注释里写死了原因：

- **anime.js v4 删掉了 `ease: 'cubicBezier(...)'` 字符串语法。**
  遇到它只 warn 一句然后按无缓动处理 —— 动画照跑、画面照出，只是全部变成匀速。
  必须 `import { cubicBezier } from 'animejs'` 传函数。
- **同一元素上的第二条动画不能用 `fill: 'both'`。**
  它的反向填充会在自己还没开始时就把起始值盖上去，而且合成顺序更高，直接压掉前一条。

## 落地的四条路

方案排好之后，`ExportPanel` 按「你手上有什么」给出口，不是给一堆按钮让你猜：

| 路 | 适合 | 成本 |
| --- | --- | --- |
| **剪映专业版操作单** | 不想碰命令行 | 零 |
| **video-use 交接指令** | 有原片、要词级时间戳吸附切点 | 零（本地 ffmpeg） |
| **Seedance / 即梦（静图→视频）** | 静图多、视频少，想要真运镜而不是假的 Ken Burns | 即梦有免费额度；fal.ai 约 $0.22–0.47/秒 |
| **Higgsfield Vibe Motion** | 图表动画、数字滚动、手写做不动的复杂版式 | 按额度 |

剪映操作单里每个数字都算好了：第几秒按 `Ctrl/Cmd+B` 分割、静图关键帧缩放到百分之几、
调色六个滑块各拉多少（`constants.js` 里每档调色都配了 ffmpeg 和剪映两套参数）。
字幕直接导 `master.srt`，时间戳对得上，不用重新对轴。

> **为什么不直接生成剪映草稿文件**：剪映 6.0 起 `draft_content.json` 已加密，
> 社区那些改草稿的库只对 5.9 以下或特定 Windows 版本有效，逆向来的、版本一升就废。
> 操作单慢一点，但永远不会失效。

### Higgsfield MCP

仓库根目录的 `.mcp.json` 已经配好远程 HTTP 端点，在这个仓库里开 Claude Code 就能用：

```jsonc
{ "mcpServers": { "higgsfield": { "type": "http", "url": "https://mcp.higgsfield.ai/mcp" } } }
```

首次调用会走浏览器授权（用 Higgsfield 账号），不用往仓库里放任何密钥。

## 已知边界

- **趋势那一屏不接实时数据。** 它做的是「格式为什么有效 + 你该怎么做出不一样的」。
  把你最近刷到的爆款粘进输入框，输出质量差两个档次 —— 模型的知识有截止日期，你的观察没有。
- **封面出图不写中文大字。** 模型写中文容易出错别字，所以 prompt 只负责画面和留白，大字自己叠。
- **抽帧模式听不到声音。** 涉及口播和音乐的判断会标「推测：」，自己核一下。
- **时间码是模型看出来的，不是解码出来的。** 导出的 in/out 已经夹回素材真实时长内，
  但真正的精度来自渲染端用词级时间戳做吸附 —— 这也是推荐走 video-use 的原因。

## 出图：Creative Director 引擎

出图这条线不是把文案里那句话直接丢给模型，而是过一道 `services/imagePrompt.js`
（方法论固化自 `.claude/skills/banana`，对齐 Google 2026-03 官方提示指南）：

- **5 段式公式** — 主体 → 动作 → 场景与时间 → 构图 → 风格（光线在风格里）。写成叙述段落，不是逗号关键词列表。
- **禁用词拦截** — `8K / masterpiece / photorealistic / ultra-realistic / highly detailed / award winning …`
  这些词会被 Nano Banana 的系统提示**主动惩罚**，出图前统一洗掉，并告诉你洗了哪些。
  分辨率靠 `imageSize` 参数控制，不是靠在 prompt 里喊。
- **5 个 domain** — 空间全景 / 单品 / 材质微距 / 生活场景 / 封面。
  每个自带真实相机型号、镜头光圈、光线方案和 prestigious anchor（Architectural Digest、Wallpaper*、Kinfolk）。
- **安全拦截 → 具体改写建议** — 被过滤器拦下时指出触发点并给三条改写方向，而不是让你自己猜。
- **不点名木材树种** — 讲木纹与质感，对齐品牌表达规范。

模型：`gemini-3.1-flash-image-preview`（Nano Banana 2），兜底 `gemini-2.5-flash-image`。
> ⚠️ `gemini-3-pro-image-preview` 已被 Google 于 **2026-03-09 关停**，调用会硬报错，不要放回候选列表。
