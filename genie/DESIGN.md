# WISH 设计说明 —— 为什么这样设计

> 一句话：**先读懂一个家，再把它变出来。**
> 客人第一次到展厅，先跟熊猫精灵「潘吉」走一趟 6–8 分钟的**许愿之旅**，把心里的家说出来；
> 设计师接着把平面图 + 客人的答案，马上变成看得见、能换材质、能拖太阳的 3D 概念。

---

## 0. 要解决的问题

第一次见面时没有任何「看得见」的东西，于是：

- 客人说不清楚（「我要简约一点的」—— 每个人的简约都不一样）；
- 设计师只能猜，第一版方案常常方向就错；
- 细谈阶段反复改，浪费双方时间，也伤信任。

所以 WISH 做两件事：

1. **把需求问出来** —— 用游戏的方式，让客人在轻松、有仪式感的状态下，说出真实偏好、真实的东西数量、真实的雷区；
2. **把需求变出来** —— 当场生成 3D 概念，让对话从「空讲」变成「对着看得见的东西讲」：*这是不是你要的？*

---

## 1. 两个分开的功能

| | 许愿之旅 `quiz.html` | 3D 梦想工作室 `studio.html` |
|---|---|---|
| 给谁 | 客人（展厅 iPad / 手机） | 设计师、销售（电脑 / 展厅大屏） |
| 多久 | 约 6–8 分钟 | 不限 |
| 产出 | 「专属梦想家概念蓝图」（客人版 + 设计师版）、分享海报、WhatsApp 摘要 | 3D 概念、带品牌的高清概念图、分享链接、演示模式 |
| 能单独用吗 | 能 | 能（没有许愿档案时用三个情绪预设） |

两者用一条链接串起来：蓝图页「在 3D 里看见它」→ `studio.html#p=<档案>`。档案里的材质、收纳量、
生活习惯（神台、宠物、在家办公、鞋量、衣柜量）会自动套进 3D 的材质和家具摆放。

## 2. 用《快思慢想》的逻辑设计许愿之旅

卡尼曼把人的思考分成两套系统：**系统 1** 快、凭直觉、不费力；**系统 2** 慢、要计算、很耗能。
问卷之所以无聊又不准，是因为它**一直在逼系统 2 回答系统 1 才答得好的问题**（「你喜欢什么风格？」），
却又**让系统 1 去回答系统 2 才答得准的问题**（「你大概需要多大的衣柜？」—— 随口一说）。

WISH 把两者分开，并把书里的概念一个个落成具体功能：

| 心理学概念 | 意思 | 在 WISH 里的做法 |
|---|---|---|
| **系统 1 / 系统 2** | 快直觉 vs 慢思考 | 第一张牌「直觉」：12 组图片二选一，提示「跟着第一感觉走」（独自玩时有一条不催促的计时线，两人 / 一家人一起玩时不计时）。第三张牌「宝藏」：潘吉换上放大镜，明说「现在请慢下来」，数鞋、数衣柜、数书。|
| **替代效应** | 人遇到难题会偷偷换成简单题来回答 | 我们主动替客人换：不问「你喜欢什么风格」，问「哪一个房间让你想马上躺下」「光着脚想踩在哪里」。风格由我们从答案推算（四条轴 → 16 张牌）。|
| **认知放松** | 越流畅、越熟悉，越愉快、越信任 | 一屏一题、大图少字、生活语言；按钮大、反馈快（音效、翻牌、萤火）；每一关背后是一处安静的自然风景。|
| **反应时** | 越快 = 越确定 | 只在独自玩时参考：和客人**自己的**中位数比（快于 0.7 倍算快、慢于 1.5 倍算犹豫，第一组不算），权重只轻轻调整。屏幕上不夸「秒选」（不奖励草率）。设计师版列出「选得最快的几题（参考）」，沟通建议以「参考：」开头。|
| **框架效应** | 同一个问题，换个说法答案就不同 | 用生活场景提问：「星期六早上 10 点你在哪里」「推开家门第一件事」「门铃突然响了最想藏什么」。|
| **损失厌恶** | 对讨厌 / 失去的东西，比喜欢的更敏感、更确定 | 第五张牌「雷区」只问**绝对不要什么**（颜色、质感、玻璃柜门、开放层板…）；系统会自动把踩雷的材质换成最接近的安全选项（每个材质都登记了色系，换的时候不会凭空多出新颜色）。「门铃响了」那题问的是痛点，而不是愿望。|
| **聚焦错觉** | 想到什么，什么就显得最重要 | 第四张牌「三个愿望」：12 个愿望只能选最想要的 3 个。逼出真正的优先级，而不是「每样都很重要」。|
| **位置偏差 / 默认值** | 排在前面、默认选中的，更容易被选 | 二选一的左右每次随机；12 个愿望每次打乱顺序；藏 / 展滑杆没动过就不计分；宝藏的数字没动过，设计师版标「默认值，未确认」。|
| **锚定**（善用，也防误用） | 第一个看到的数字会影响判断 | 数鞋子时实时换算成「鞋柜 ≈ 2,100mm」—— 用工程常识帮客人估得更准；**预算不在许愿之旅里问**（避免被我们的数字锚定，预算仍在需求卡 / 面谈时谈）。|
| **眼见即一切（WYSIATI）** | 人只根据眼前的信息下判断 | 这正是 3D 工作室存在的理由：客人只会对看得见的东西有判断，所以要让他马上看见。|
| **峰终定律** | 体验被记住的是最高点和结尾 | 峰：暮色里洗牌 → 一张牌升起、翻面，萤火亮起，写着「因为你……」。终：盖着「潘吉认证」印章的蓝图 + 熊猫道别 + 可以带走的海报。|
| **经历自我 vs 记忆自我** | 回忆比当下更决定人的选择 | 蓝图链接 + 分享海报：客人回家打开 / 发给家人，体验再发生一次（也是口碑）。|
| **光环效应** | 一个好印象会扩散到其他判断 | 精致的牌面、可爱的熊猫、顺滑的动效 —— 先让客人感受到「这家公司很细心」。|

**伦理底线**：这些原理用来**帮客人说出真实需求**，不用来制造假紧迫、不在测试里推销、不锚定预算。
设计师版里「直觉型 / 比较型」的判断，是为了用客人舒服的方式沟通。

### 四条轴 + 三条暗轴

| 轴 | a 侧 | b 侧 | 影响 |
|---|---|---|---|
| 温度 | 暖 W | 清 C | 色温、木色、墙色 |
| 密度 | 简 M | 丰 L | 软装数量、留白 |
| 质感 | 朴 N | 雅 R | 自然材质 vs 石材金属烤漆 |
| 收纳 | 藏 H | 展 D | 柜门比例、玻璃展示柜、开放层板 |
| 暗轴：明度 / 线条 / 社交 | 明亮 / 圆润 / 相聚 | 沉稳 / 利落 / 独处 | 时间预设、沙发款式（弧形 / L 形）、餐桌座位数 |

16 张牌（I–XVI）每张都写成「被看见」的样子（没有坏牌）。每张牌附带：整套 3D 材质、配色、
设计语言（风格 / 色温 / 柜门 / 藏展比例）和**可以直接贴给 AI 出图的英文关键词**。

## 3. 为什么玩 The Sims 不无聊，设计房子却很累？

The Sims 的「建造模式」本质上就是室内设计，但人会玩到忘记时间。拆开看，它做对了这些事 —— WISH 照着做：

| The Sims 做对的 | 为什么让人停不下来 | WISH 3D 工作室 / 许愿之旅 |
|---|---|---|
| **即时反馈** | 每个动作马上有结果，大脑一直拿到小奖励 | 拖材质 → 那一组表面发金光、放手马上换；数鞋 → 鞋柜马上变长；拖太阳 → 光马上走 |
| **零成本试错** | 不怕选错，才敢一直试 | 撤销 / 重做；「一键情绪」随时回去 |
| **需求条** | 一组会动的数字，告诉你「变好了」 | 情绪仪表 COZY / BRIGHT / MOODY，跟着材质和时间实时变化，还有一句话描述 |
| **时间在流动** | 有生命的世界 | 24 小时光影：清晨薄光、斜进窗的光柱、窗上的树影、夜里亮起的灯 |
| **有限而精选的目录** | 选择太多会瘫痪 | 每类约 10 个材质，按 Wood / Stone / Tile / Fabric / Paint / Metal 分好 |
| **直接操作** | 手比菜单快 | 拖材质、拖家具、拖太阳；点一下家具 = 旋转 / 换款 / 复制 / 移走 |
| **为「人」设计** | 你在照顾一个小人，所以有情感 | 家具按客人的生活自动摆：神台、宠物窝、玩具柜、书桌、鞋柜长度、衣柜长度 —— 「这是**我的**家」 |
| **小目标 + 进度** | 未完成的事会一直挂在心上（蔡格尼克效应） | 许愿之旅的五块踏脚石（跨过一条溪）、「蓝图完成度」百分比 |
| **惊喜** | 不确定的奖励最上瘾 | 洗牌揭晓、彩蛋式的熊猫台词、风景跟着每一关换 |

## 4. 设计师视角：它替你做了什么

**见面前 / 见面时**

- 蓝图「设计师版」（只有员工看得到）：风格、色温、柜门、藏展比例、色号、选得最快的几题（参考）、英文出图关键词；
- **按生活方式自动换材质**（列在设计师版，不算雷区）：有猫狗 → 沙发避开丝绒 / 羊羔绒；天天爆炒 / 有小孩 → 天然石台面换成同花色的石英石 / 岩板；
- **谈话提示**：自动找出矛盾和风险，例如
  - 天天爆炒 + 喜欢开放热闹 → 干湿分区、烟机风量；
  - 想展示 + 怕积灰 → 玻璃门 + 柜内灯带；
  - 有猫狗 + 选了丝绒 → 改科技布 / 皮革；
  - 选了深色系 + 想要明亮 → 深色只用在主题墙；
  - 需要神台 / 长辈同住 / 在家办公 / 大件多 → 对应尺寸与预留；
  - 有风水师 / 有要遵守的方位 → 定平面前先拿到要求。
- **收纳蓝图**：鞋柜宽、衣柜目标宽（长挂 / 短挂 / 叠放）、书墙长度、家电台面与电器高柜、储物间建议。

**3D 工作室**

- 上传平面图（图片 / PDF）→ AI 认出房间、门、窗（Gemini，选填）→ 拖一拖校正 → 生成 3D；
- 家具按设计师规则自动摆：电视墙选最长无窗的墙、沙发离电视 2.7–3.3m、床头靠无窗墙且两侧留 50cm、
  衣柜前留 60cm、橱柜沿最长墙并避开窗、够大就做 L 形 / 岛台……
- 厨房按「冰箱 – 水槽 – 炉头」的工作距离排，炉头不进转角；岛台、餐椅留够通道；
- **收纳对账**：客人要的鞋柜 / 衣柜 / 书墙长度 vs 方案里放下的，差多少一眼看到；
- 换材质、换情绪、换时间、挪家具，全部可撤销；下载带品牌的概念图；演示模式给展厅大屏 / 录屏宣传。

**局限（要跟客人讲清楚）**：这是**概念示意**，不是施工图；尺寸以现场量尺为准；家具是程序化的示意款。

## 5. 客人视角：第一次到展厅的 60 分钟

| 时间 | 发生什么 | 客人的感受 |
|---|---|---|
| 0′ | iPad 上选「中文开始 / Begin in English」，「擦亮神灯」，潘吉从晨雾里出来 | 好可爱 / 有点好奇（仪式开始） |
| 1′ | 直觉之牌：12 组二选一（背后是稻城亚丁的雪山） | 轻松、好玩、「它好像懂我」 |
| 2′ | 生活之牌：周六早上、门铃响了 | 被问到生活，而不是被考设计 |
| 3′ | 宝藏之牌：数鞋、衣柜、书、家电、大件 | 「原来要想这些」—— 被认真对待 |
| 5′ | 三个愿望 | 第一次想清楚自己最在乎什么 |
| 6′ | 雷区之牌 + 一句话 | 说出讨厌的东西，很爽快 |
| 7′ | 暮色里洗牌、翻牌：「I · 暖木禅居」 | **峰值**：被看见 |
| 8′ | 蓝图（盖章）+ 海报；音乐渐弱，让位给对话 | 有仪式感，可以带走、可以晒 |
| 10′–50′ | 设计师打开 3D：上传平面图，套用他的材质；一起换材质、拖太阳 | 「这就是我想要的」/「这个不是」—— 具体的对话 |
| 结尾 | 下载概念图、WhatsApp 发链接 | 回家还能再看一次（记忆自我） |

## 6. 氛围：许愿模式、风景、颜色

- **VI「晨光溪岸」**：白天的纸、湿石头、溪水；金色只留给少数重点。暮色只在仪式时刻（擦神灯、翻牌、揭晓），
  像傍晚的萤火 —— 平常是清醒、明亮、好读的，仪式时才变魔法。3D 画布保持深色，让材质和光说话。
- **风景**：每一关一处马来西亚 / 四川的自然（金马伦、稻城亚丁、大汉山、九寨沟、京那巴鲁山、四姑娘山、瓜拉雪兰莪的萤火虫），
  像旅行杂志 —— 让人放松（认知放松），也悄悄告诉客人「家和自然是一起的」。
- **音乐**：大自然禅意声景只为许愿时的专注；揭晓之后渐弱（蓝图约一半、3D 约四分之一），把空间让给客人和设计师的对话。
  颂钵、风铃默认关闭（有些客人忌讳风铃）。
- **风水**：系统只避开实际问题 —— 噪音、湿气、油烟（床头不靠浴室墙、神台不背厕所厨房）；方位类风水不写进蓝图、海报、WhatsApp，
  有风水师或有要遵守的方位时，由设计师见面时处理。
- **颜色的来源**：界面颜色只用 `src/shared/base.css` 的变量；canvas / three.js 读不到 CSS 变量，用 `src/shared/palette.js`。
  材质、测验图片、日光、风景这些「内容色」写在各自的资料文件里，不跟着 VI 换。
- **状态栏颜色（theme-color）**：入口页 / 许愿之旅 / 许愿模式用纸色 `#F3EEE4`；3D 工作室是有意的例外，用画布的深色
  `#121611`（= `--studio-bg`）—— 整页是深色 3D 画布，状态栏跟着画布才不会在顶上多出一条纸色带子。
- **客人版 / 设计师版**：设计语言、色号、谈话提示、收纳对账、别的客人的方案，只在员工入口（`?staff=1`、员工蓝图、许愿模式的员工区）出现；
  许愿模式永远是客人版。3D 的「设置」（公司的 AI key、模型、接口）也只在员工入口出现（`?staff=1` 或设计师自己的方案），客人版和许愿模式里没有。
  客人自己按「发给设计师」时，WhatsApp 文字只放客人版蓝图上本来就有的东西，链接也是客人版。
- **这台设备留着的客人资料，留多久**（PDPA：不需要了就删；`CONFIG.keepDays` 天，默认 90，0 = 不自动删；没有日期的旧记录先留着）。
  过期的读的时候就真的删掉（不只是不显示）；入口页、许愿模式一打开、每一次「下一位客人」也会扫一次（`src/shared/keep.js` 的 `sweepKept`），
  员工没打开名单也会按时删：

  | 存在哪里 | 里面是什么 | 从什么时候算 | 怎么删 |
  |---|---|---|---|
  | `localStorage` `genie.profiles.v1` | 本机蓝图（客人的答案、卡牌、家） | 建好那天 | 到期自动；入口页员工区删一份 / 「清空本机全部蓝图」 |
  | `localStorage` `genie.leads.v1` | 客人名单：称呼 + WhatsApp 号码 + PDPA 同意（时间、版本）+ 员工记的预算 | 这位客人最后一次留资料 | 到期自动；许愿模式员工区「清空名单」（先导出 Excel） |
  | `localStorage` `genie.staffnotes.v1` | 员工记的预算（只在许愿模式 / `?staff=1` 问；永远不进档案、链接、WhatsApp） | 最后一次改 | 到期自动；跟着蓝图删（删一份 = 删它的预算，清空 = 全清） |
  | IndexedDB `genie-handoff` | 客人的户型图原图 + 读出来的平面图（交给 3D 用） | 存进去那天 | 到期自动（`handoff.js`） |
  | IndexedDB `genie-boards` | **没有客人资料**：溪岸板材的记录 + WebP 贴图（员工导入的 / 展厅 iPad 导入的板材包）、导入器的分析缓存（键是文件名 + 大小 + 日期，不存路径）；客人的手机看有板材的案例时只会多一个空的库 | 员工导入那天 | 板材库里「从这台设备删掉」；不会自动删（是公司的产品资料，不是客人的） |
  | `sessionStorage` `genie.boardsLean` | **没有客人资料**：显卡掉过一次之后，这个分页先用小一点的板材贴图（存的是时间，只有 15 分钟内算数） | 显卡掉线那一刻 | 关掉分页；许愿模式「下一位客人」也会清掉 |

  这些都只在这台设备上，不经过任何服务器；离开这台设备只有客人自己按的分享 / WhatsApp，和员工自己导出的 Excel。
